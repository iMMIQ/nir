# M3 验证记录

验证日期：2026-09-24。M3 实现、功能回归、正式性能对比及完整两小时硬件运行已完成。功能、预算和清理检查通过；进程物理内存仍有小幅上移，循环耗时也增加，不能将本轮结果表述为物理内存或长期吞吐完全稳定。

可复核的标量样本、环境、报告 SHA-256 和测试结果见 [summary.json](summary.json)。完整阶段追踪保留在本地 `reports/`；精简证据已随本文纳入项目。

## 基线

代码与 SDK 基线为 `711a859`。保留 SDK／CLI／发行副本，用同一 32 章、66 条历史、每轮 30 次恢复工作负载复测三轮，Playwright trace 关闭，运行时诊断开启。

| 轮次 | 中位数 | P95 | 最大值 |
|---|---:|---:|---:|
| 1 | 254.2 ms | 13706.0 ms | 15763.6 ms |
| 2 | 273.95 ms | 20780.8 ms | 24290.4 ms |
| 3 | 260.95 ms | 4555.8 ms | 20920.6 ms |

原始报告在 `reports/m3-before-{1,2,3}/`。长尾在基线反复出现，不能将其出现本身归因于 M3 改动。

本机根分区／`/tmp` 与工作区位于同一接近满容量的 Btrfs 设备；诊断期间 Linux I/O PSI 显示明显的系统级等待。Playwright 默认传入 `--disable-dev-shm-usage`，因此需要分别检查 HTTP 缓存、浏览器临时目录与共享内存路径。系统压力是背景条件，不能只凭 PSI 将某个请求归因于特定进程。

## 实现与验收方法

接口、预算及复现入口见 [M3 准备调度](../../M3-PREPARATION.md)。恢复诊断同时关联服务端、CDP 和系统压力；额外诊断与正式耗时轮分开。媒体场景使用每章独占对象、确定的相邻 Cue，预取开关交替配对，阅读停顿固定一秒。

长稳使用双分支作品和独立多模块路线，交错保存恢复、回退、语言切换及设备重建，在返回标题的同一阶段采集账本和进程内存。短时验证不能替代完整两小时运行。

## 同环境正式对比

使用保留的基线 SDK 与最终 SDK，Chromium 153、NVIDIA Ampere 非 fallback 适配器、原生共享内存、磁盘临时目录、关闭 Playwright trace。限速网络为 40 ms 延迟、20 Mbps 下行和 5 Mbps 上行。清理可重建的 Rust 增量缓存后，前后轮均在相同存储政策下执行；早先磁盘共享内存诊断不混入这组引擎对比。

| P95 指标 | 基线 | M3 |
|---|---:|---:|
| 本地网络首句，隔离上下文 | 969.2 ms | 953.4 ms |

| 限速首句，隔离上下文 | 1924.5 ms | 1931.2 ms |

启动每种缓存条件 20 次；32 章每个开关 5 轮、165 次章切换。启动和正常规模路径未见超过 10% 的 P95 退化。容量场景的恢复每个开关只有一个样本：第一次关闭预取为 225.1→248.3 ms，触发复核；补测为 235.7→230.1 ms，未复现同向退化。该场景验证超过缓存预算时的驱逐及恢复正确性，不能凭单样本声称统计显著。

## 完整两小时运行

目标 7200 秒，实际 **7201.78 秒、1318 轮、131 次设备重建**，264 次独立多模块路线。每轮校验双分支之一、保存恢复、回退、标题清理；每五轮走多模块路线，每十轮重建设备。短时同脚本另跑 121.83 秒、29 轮并通过。

所有剧情、预算与清理等待断言通过。1318 个快照的资源／解码／上传队列及请求槽均为空；其中 6 次在清理等待通过后、单独读取快照前又到达一个 owner 回调，快照计数为 1，其余为 0。原始记录保持不变，不能称每个快照的所有回调均为零。当前脚本已把清理条件判断和快照捕获合并为同一次浏览器调用；同一生产 SDK 补测 122.68 秒、29 轮通过，所有快照的队列、请求槽及回调均为零，内存采样覆盖率 100%。补测报告位于 `reports/m3-longrun-snapshot-check/`，不替代或改写两小时记录。

RSS、PSS、JS 堆有效采样覆盖率均为 100%。媒体估算账本随文本语言在 57252999–57355943 字节之间切换。主页面 WASM 首轮容量为 9109504 字节，预热后固定在 12845056 字节（12.25 MiB）。

## 测量边界

- 本机 Chromium、Linux、真实 Vulkan GPU；不代表移动设备、Firefox/Safari 或其他平台通过。
- Linux RSS 是进程驻留页之和，可能重复计算共享页；PSS 按比例分摊共享页，统计 CDP 返回的浏览器进程（含两个页面）。JS 堆及 WASM 容量只记录主作品页面。
- 长稳在标题页等待资源、解码、上传、请求槽及 owner 回调清空后采样。文本语言每两轮切换，与每轮交替的结局形成四种组合；UI 语言固定。硬件运行要求内存各项有效采样覆盖至少 95%。
- GPU 物理分配未测量；128 MiB 媒体估算账本不等于进程或显存上限。
- 单 Cue 预取依赖目录已驻留、确定的下一条路径及可用预算；同步 PNG 解码等原子调用仍可能超过时间片。
