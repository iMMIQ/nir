# 启动与跨章优化验证

日期：2026-09-24。沿用 M2.3 的工作负载，本轮重新采集关闭 Playwright trace 的优化前后数据；运行时诊断均开启，不把历史 trace 开启样本混入对照。

## 实现

- 发行清单验证后并行获取 WASM、JS、host 和运行时根对象；各自验证后才导入，所有启动依赖验证完成后才实例化 WASM。失败取消下载并等待所有任务结束。
- 编译器为可缩小的 WASM／JS／JSON 生成固定时间戳的 gzip level 6 旁文件。预览服务协商编码、保留 MIME／缓存／Vary，校验器检查解压后的身份；不支持 gzip 时使用原文件。
- 章节批次最多四个 worker，共用全局四槽资源池；对象去重、顺序交付、原子安装、优先级提升和取消语义保持。最后一个内容消费者取消时仍等待底层校验结束，避免提前释放 staging。正式请求只在确有暂存压力时回收预取，并向 Rust 返回终态；同时覆盖回收后的请求提升与取消竞态。
- 回归暴露并修复两处加载时序问题：返回标题必须等待标题媒体就绪再绘制；暂停音频的准备阶段不能等待可能被 suspend 延后的 resume promise。历史、滚动、对白 Gate 和原有纹理回收继续工作。
- ResourceTiming 增加请求、首字节、响应结束及连接阶段；运行时记录资源池开始下载和独立校验区间。

源格式 1、运行时格式 2、存档格式 1 不变。驻留及 staging 各 16 MiB、预取最多 2 MiB，按解压后的对象编码字节计费。没有引入自动重试、任意超时、Worker 或新的渲染架构。

## 条件与方法

使用同一台 Ryzen 9 5900HX／RTX 3080 Laptop、同一 NixOS、Chromium 153、NVIDIA 原生 Vulkan 和 Xvfb。每个上下文记录引擎实际适配器并拒绝软件／fallback 设备；环境原始信息见 `summary.json`。

- loopback 与 CDP 限速各 20 次独立上下文启动、20 次同上下文热重载。
- 限速为 CDP latency 40 ms、下载 20 Mbps、上传 5 Mbps，不代表实际公网 RTT；不限制 CPU。
- 限速 32 章，预取开／关各 5 轮，交替配对顺序，每种配置 165 次章节输入到目标对白提交。固定章前停顿 1 秒，不等待预取完成。
- 优化后另跑 32 章容量配对，合成代码包按解压后大小超过 16 MiB；旁文件随重算后的对象身份生成。
- 性能测量期间没有并行构建或其他测试套件。后台桌面负载未被隔离，不作为通用硬件性能保证。

独立上下文隔离 HTTP 缓存，共用浏览器／GPU 进程，不等于冷进程启动。热重载保留实际缓存命中计数。渲染提交不等于像素到屏幕；rAF 间隔不是 GPU 执行时间，物理内存未测量。

## 结果

最终 4 项真实 GPU 测试全部通过，耗时 12.3 分钟。同目录 [summary.json](summary.json) 归档前后统计、原始标量样本、环境、容量账本、最慢切换事件、异常资源与源报告 SHA-256。

| P95 指标 | 优化前 | 优化后 | 变化 |
|---|---:|---:|---:|
| loopback 独立缓存启动 | 2062.0 ms | 2109.0 ms | 增加 2.3% |
| loopback 热重载 | 1675.5 ms | 1645.7 ms | 减少 1.8% |
| 限速独立缓存启动 | 5222.2 ms | 2662.0 ms | 减少 49.0% |
| 限速热重载 | 4528.9 ms | 1720.1 ms | 减少 62.0% |
| 32 章切换，关闭预取 | 176.6 ms | 79.6 ms | 减少 54.9% |
| 32 章切换，开启预取 | 31.1 ms | 25.8 ms | 减少 17.0% |

优化后的限速冷启动中位数为 2638.8 ms、最大值为 2672.8 ms；热重载中位数为 1650.7 ms、最大值为 2174.0 ms。本机冷启动没有改善，不能把限速场景的收益外推到所有环境。

最终 WASM 为 6,787,203 字节，gzip 为 1,485,712 字节，减少 78.1%。32 章每轮内容对象传输量（包含 ResourceTiming 的头部估算）从 98,283 降到 61,243 字节；逻辑对象请求仍为 101 次。内容驻留峰值仍为 69,169 字节，暂存峰值仍为 13,712 字节，没有用扩大预算换取速度。开启预取的 165 次切换均在输入前内容就绪，中位数仍为 17.3 ms；本轮主要收益来自未预取时的等待减少。

容量场景总内容为 21,027,928 字节，超过 16 MiB 预算；内容驻留峰值为 16,424,495 字节，暂存峰值为 656,397 字节。预取开关两条路线均通过驱逐、重载、剧情等价与恢复检查，结束时活动请求、暂存占用、暂存预约及等待需求均为零。限速和容量场景均无账本违规。

### 剩余长尾与后续工作

- 最慢章节切换仍为 558.3 ms（预取开启，第 1 轮 ch31）。内容已提前就绪，本次没有网络请求；事件显示资源排队后到首个渲染提交相隔约 535 ms，随后命中字节缓存并完成准备。这将后续排查范围指向主线程／渲染提交阶段，但现有记录不能区分同步渲染、浏览器调度及 GPU 等待。下一步应针对该区间增加细分计时并采集浏览器性能轨迹。
- 首次进入 ch01 的媒体准备仍约 0.5 秒；当前内容预取不包含媒体 lookahead。关闭预取的恢复操作只有 5 个样本，P95 从 385.2 ms 升到 468.8 ms，中位数则从 364.2 ms 降到 295.0 ms；不能宣称所有交互都有稳定改善。
- 资源池等待 P95 为 0.1 ms，对象校验 P95 为 0.2 ms，下载及读取 P95 为 51.0 ms；本轮最长下载及读取仍为 814.3 ms，预取掩盖了它对输入等待的影响。历史 trace 开启时的 21 秒切换没有在本轮复现，根因仍未确认。
- 中间版本的一次 32 章限速测试曾超时，后续审查修复了宿主回收预取却不通知 Rust 的协议缺口。该次失败未采集到足够的现场状态，不能断言二者存在确定因果。最终版本完整 5 组配对通过；测试现已在失败时保存宿主队列、内容请求、状态与资源时序。
- 中间版本还出现过 4.71 秒本机启动（Engine.create 区间约 3.13 秒）和 8.57 秒限速启动（bootstrap 开始前约 6.05 秒）。最终采样未复现，仍保留为待解释的异常，不能视为已消除。中间数据保存在 `reports/startup-content-intermediate/`，未混入上表。

后续优先细分主线程与渲染等待，再评估媒体 lookahead／按帧上传预算；另行进行长时间稳定性测量。当前固定路线通过不等于数小时长稳验收，也没有建立跨机器耗时硬门槛。

## 功能验证

- 45 项宿主测试通过，包括乱序完成、去重、全局并发、失败收敛、预取提升、取消共享消费者及不可取消校验的生命周期。
- 46 项 compiler／CLI Rust 测试通过，包括压缩可复现性、协商与回退、响应长度／缓存头、路径安全以及损坏旁文件拒绝；另有 8 项 Rust 内容协议测试通过，覆盖提升后跳过、恢复与取消。
- 最终构建的 34 项浏览器测试通过，覆盖两个结局、字体与语言、作者预览、长文本与 Gate、存读档／回退、真实设备恢复、启动并行及压缩传输。
- 独立 SDK 测试、发行图与 gzip 校验、损坏／解压内容错误拒绝、缺少可选旁文件回退、依赖边界和格式检查通过。

## 复现与产物

```sh
nix develop --command cargo xtask sdk
dist/novelc -p examples/rain-letters resolve
dist/novelc -p examples/rain-letters build --locked --out dist/rain-letters-web
python3 scripts/verify_release.py dist/rain-letters-web
bun run test:performance:hardware --trace=off --grep 'navigation baseline|module scale (shaped-32|capacity-32)'
```

硬件入口需要 `CHROMIUM` 与显示环境；无 DISPLAY 时指定 `XVFB_RUN`。本机路径及启动参数保存在环境记录中。部署配置见 [作者说明](../../AUTHORING.md#静态发行的压缩传输)。

完整本地产物保存在忽略目录 `reports/startup-content-before/` 和 `reports/startup-content-after/`；最终浏览器结果为 `reports/startup-content-browser-final.json`。本目录保留可审阅摘要，不将数十 MB 的逐事件记录提交到仓库。
