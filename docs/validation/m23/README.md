# M2.3 规模性能测量

测量日期：2026-09-23。本轮提供可重复的基准和确定性门禁，不实施性能优化。原始报告位于工作区 `reports/`；归档摘要、逐次耗时和原始报告 SHA-256 见 [summary.json](summary.json)。

## 环境与口径

- NixOS / Linux 6.18.45，Ryzen 9 5900HX，32 GiB 内存，RTX 3080 Laptop（16 GiB 显存），NVIDIA 驱动 595.71.05。
- Chromium 153.0.8010.52，原生 Vulkan，X11/Xvfb 1920×1080，页面 1280×800。引擎实际取得的适配器报告 `nvidia / ampere / fallback=false`；不是独立请求另一个适配器来代替证明。
- loopback 和 CDP 网络配置分开测量：后者设置 40 ms 延迟、20 Mbps 下载、5 Mbps 上传。CDP 模拟不等于真实公网；以资源 timing 核对实际缓存命中。
- 新 context 隔离浏览器缓存，仍共享浏览器／GPU 进程。每组配对交替预取开关的先后顺序，固定 1 秒章前阅读时间。
- 本次同时开启运行时诊断与 Playwright `retain-on-failure` 追踪（包含截图／快照采集）。数据包含观测开销，长尾不能直接归因于引擎；关闭追踪需要单独重建基线。
- 3／32 章语义场景使用正式编译产物，每章一段对白，复用媒体，另有一个独立主流程模块。容量场景给代码对象补合法 JSON 空白，明确与语义耗时分开。

## 验收内容

宿主测试覆盖真实适配器判定、输入与目标对白提交关联、无样本／无效样本统计以及增量追踪的丢失检测。软件 CI 冒烟覆盖 3 章配对和完整的 32 章容量检查。

完整硬件套件包括两种网络下冷／暖启动各 20 个样本、30 次恢复／返回标题循环（包含 3 次 GPUDevice 销毁），以及每种网络和规模的 5 组预取配对。容量配对仅运行一次，是确定性检查，不是性能基线。

预算、清理、预取确实启用／关闭、剧情等价、选择语言范围和驱逐后重载作为失败门禁。首句 4 秒、已准备输入到提交 50 ms 是对照目标，不是本轮强制耗时门槛。

实际结果：**36 项宿主测试、2 项软件渲染冒烟、8 项完整真实 GPU 用例通过**；完整硬件套件耗时 27.4 分钟，0 失败、跳过或 flaky。30 次恢复的活动请求均归零，设备代次从 1 增至 4。

最终另用 2 项少样本检查验证硬件入口移除 Playwright 默认的软件 fallback 许可及新增报告元数据；这组不替代上述完整样本。完整原始结果保存在 `reports/m23-hardware-full/`，软件冒烟在 `reports/m23-ci-smoke/`，最终入口检查在 `reports/m23-hardware-final-smoke/`。

## 实测结果

### 启动与已准备输入

每行 20 个样本；时间为 P95。

| 网络／缓存 | 导航到首句 | 菜单输入到提交 |
|---|---:|---:|
| loopback／新 context | 3890.5 ms | 3.4 ms |
| loopback／暖重载 | 1634.1 ms | 2.9 ms |
| 40 ms、20 Mbps／新 context | 5092.4 ms | 3.1 ms |
| 40 ms、20 Mbps／暖重载 | 4877.7 ms | 3.4 ms |

限速首句未达到 4 秒建议目标；菜单输入达到 50 ms 建议目标。暖重载每次 16 个对象请求中有 15 个零传输字节。活跃 rAF 超过 33.3 ms 的比例约为 21.6%～36.2%，未达到设计建议的 0.5%；这些包含追踪开销和 Xvfb 调度，需继续拆分原因。

### 章节切换

每种配置 5 次路线；3 章各 20 个切换样本，32 章各 165 个，均包含首章重入。

| 网络／章节 | 关闭预取 median／P95 | 开启预取 median／P95 |
|---|---:|---:|
| loopback／3 | 60.1／1317.3 ms | 9.65／369.4 ms |
| loopback／32 | 63.2／181.0 ms | 12.5／20.2 ms |
| 限速／3 | 151.9／468.7 ms | 8.0／325.6 ms |
| 限速／32 | 154.6／213.2 ms | 12.3／319.0 ms |

预取改善了各配置的中位数，未保证长尾改善。限速 32 章的预取开启组出现一次 **21,247.3 ms** 切换：第 3 次运行、ch19，预取尚未完成并被需求提升。该次一个 678 字节对象的浏览器获取区间耗时约 **18,331.1 ms**；摘要保存了这条资源记录。下一步应区分 CDP 网络模拟、预览 HTTP 服务器、宿主请求路径和追踪开销，之后再选择优化，不从这一个区间直接推断 GPU 或核心执行慢。

同规模的预取开关传输字节相同：3 章每次 11,383 字节，32 章每次 98,283 字节（标题就绪后的阅读路线资源 timing 口径，含 HTTP 开销）。阶段请求统计与实际网络传输分别保留。

### 容量与恢复

合成容量场景累计模块编码内容 **21,027,928 字节**，超过 16 MiB；每章代码对象 655,360 字节。阅读路线内第一章发生逻辑重载，后续读档没有被用来冒充重入证据。驻留、暂存峰值和恢复后请求数见摘要中的逐次记录；软件与硬件检查均通过预算和清理门禁。

这些门禁通过不改变限速启动、帧间隔和请求长尾仍需推进的结论。

## 重现

先按工程工作流构建 SDK、示例和 JS 依赖，再设置 `CHROMIUM` 与 `XVFB_RUN` 指向本机工具。测试从仓库根目录执行：

```sh
nix develop --command bun run test:host
nix develop --command bun run test:performance:hardware --max-failures=1
```

软件门禁另设置 `.github/workflows/engine.yml` 中的 SwiftShader/Vulkan 参数，然后执行 `bun run test:performance:smoke --max-failures=1`。本地结果不代替 GitHub 工作流执行结果。

## 限制

导航首句指标包括测试驱动从标题开始的延迟；章节指标包含首次章节的资源／排版准备及最后一次重入。小场景的 P95 容易受首次准备影响，不能单独代表稳态章节切换。

渲染提交不等于实际显示；rAF 间隔不等于 GPU 执行时长。真实 GPU 通过 Xvfb 运行也不构成物理显示器的帧交付验收。短路线与 30 次恢复不等于数小时长稳认证。

编码驻留、编码暂存、媒体准入估算和 WASM 线性容量分别记录。进程物理内存及 GPU 时间仍未测量。没有因功能门禁通过就宣称所有性能目标已经达标。
