# 交互与主线程优化验证

日期：2026-09-24。基线为 `11f60ac`，本轮由三个 GPT-6 Luna／max effort 子代理分别实现宿主状态、文字缓存及渲染计时，主代理审查、集成并执行浏览器与真实性能验证。

## 实现

- 正常宿主循环改读精简状态，在每次引擎状态变更后失效；完整测试／诊断状态接口保持兼容。读取语言错误不再构造整个 UI 模型。
- 用结构化画面比较代替 Debug 字符串，输入时使用局部导航布局，避免把尚未绘制的布局当成已提交画面。尺寸、DPR、首次绘制、渲染失败和 GPU 恢复强制失效，语义节点仍独立更新。
- 文字缓存改为逐项 LRU，目标 128 项；一次布局的所有键受保护，超过目标的工作集允许容纳，后续布局收敛。正常命中不扫描整个缓存，字体加载仍清空旧排版。
- 宿主、投影和渲染新增可关闭的 CPU 阶段计时；最近 64 轮明细独立于请求事件环。计时区间可能嵌套，不能直接相加，不代表 GPU 执行时间。
- 审查发现图片上传会对不透明像素重复执行浮点颜色转换。本轮增加 alpha=255 直接保留 RGB、alpha=0 清零 RGB 的快速路径；其余透明度保持原算法。上传字节预算、分行推进和完整纹理才可见的规则保持不变。

源格式 1、运行时格式 2、存档格式 1，以及内容／暂存／预取预算不变。没有引入媒体 lookahead、Worker、新后端或自动重试。

## 测量方法

前后使用相同的 Ryzen 9 5900HX、RTX 3080 Laptop、Chromium 153、NVIDIA Vulkan 和 Xvfb。验证引擎实际请求的适配器；运行时诊断开启，Playwright trace 关闭。优化版增加了详细 CPU 计时，因此前后观测开销并不完全相同。性能采样期间没有并行构建或其他测试，后台系统负载未隔离。

- loopback 与限速各 20 次独立上下文启动、20 次热重载。限速为 CDP latency 40 ms、20 Mbps 下行／5 Mbps 上行。
- 32 章限速，预取开关各 5 轮、各 165 次章节切换；沿用 1 秒章前停顿和原有回退／恢复／清理门禁。
- 32 章容量场景超过 16 MiB 编码内容，预取开关各一轮。
- 新增长历史场景：32 章、每章 40 行、66 条历史，菜单打开／关闭、历史滚动／翻页、恢复各 30 次。恢复后核对变量、对白、历史条数及逻辑位置。

HTTP 缓存隔离不等于浏览器或 GPU 进程冷启动；输入到渲染提交不等于像素到屏幕。时间仅用于本机工作负载对照，不是跨机器性能保证。P95 退化超过 10% 的项目需要复核；所有首次结果仍保留。

## 结果

完整对照的 5 项功能／预算测试全部通过。统计和原始标量见 [summary.json](summary.json)；完整本地数据分别位于 `reports/interaction-before/` 和 `reports/interaction-after/`。测试通过不表示所有耗时指标改善。

| P95 指标 | 优化前 | 优化后 |
|---|---:|---:|
| 本机独立缓存启动 | 2007.7 ms | 978.0 ms |
| 本机热重载 | 1679.9 ms | 727.5 ms |
| 限速独立缓存启动 | 2755.9 ms | 1932.5 ms |
| 限速热重载 | 1753.5 ms | 763.5 ms |
| 菜单打开 | 4.1 ms | 2.1 ms |
| 菜单关闭 | 3.9 ms | 2.1 ms |
| 历史滚动 | 4.2 ms | 2.2 ms |
| 历史翻页 | 4.1 ms | 2.0 ms |
| 32 章切换，关闭预取 | 80.2 ms | 80.4 ms |
| 32 章切换，开启预取 | 27.3 ms | 20.2 ms |
| 长历史存档恢复 | 666.1 ms | 10112.0 ms |

开启预取的章节切换中位数从 18.0 降至 13.8 ms，最大值从 507.4 降至 36.6 ms。关闭预取的 P95 基本不变，最大值从 565.7 降至 532.5 ms；优化后最慢一次为 ch11，阶段记录中最长宿主唤醒等待为 4.1 ms、事件处理为 3.8 ms，主要等待不在这些 CPU 调用中。

图片转换在长历史场景共执行 4 个上传步骤，`image.convert` 累计 3.1 ms、单步最大 1.5 ms；对应 GPU 写入调用累计 17.0 ms。文字缓存最终 76 项、24,098 次命中、76 次未命中、零淘汰；这个场景没有触发容量边界，LRU 超限行为由独立测试验证，不能将本次耗时改善单独归因于 LRU。

容量场景总内容 21,027,928 字节，内容驻留峰值 16,424,495 字节、暂存峰值 656,397 字节，均低于各自 16 MiB 上限；预取开关两条路线均通过驱逐重载、剧情一致性及请求／暂存归零检查。

### 恢复长尾：尚未解决

长历史恢复中位数从 306.65 降至 252.95 ms，但 P95 明显退化，不能宣称恢复体验已稳定改善。基线最慢一次为 21,064.5 ms；优化后出现 10,112.0 和 12,112.2 ms 两次长尾，另有一次 1537.8 ms。原始样本全部保留。

新增记录将两个最慢样本定位到 781 字节内容对象的异步下载及读取：分别约 9821.7 ms 和 11540.5 ms；对应最近宿主轮次最大仅 6.7 ms 和 7.1 ms，事件序列仍在推进。对象校验、文字准备及 GPU 提交的 CPU 阶段没有解释这段等待。这是获取路径的证据，尚不能区分浏览器缓存、连接、服务器或系统 I/O，也不能根据本轮样本证明优化导致了网络长尾。

复核另做了两轮各 30 次恢复的 CDP Network／Tracing 诊断，独立保存，不混入上表：

| 诊断配置 | 恢复中位数 | P95 | 最大值 |
|---|---:|---:|---:|
| 默认 HTTP 缓存 | 256.2 ms | 16019.0 ms | 17310.0 ms |
| 禁用 HTTP 缓存 | 290.4 ms | 6585.4 ms | 9686.0 ms |

默认缓存轮的最慢对象请求耗时约 16.90 秒，CDP 标记 `fromDiskCache=true`、传输字节为 0；禁用缓存后仍出现约 9.34 秒对象请求，标记 `fromDiskCache=false`，实际传输 728／885 字节。因此磁盘缓存不是发生长尾的必要条件，不能据此修改生产缓存策略。部分请求的响应头计时与 CDP 响应／完成事件之间有明显间隔，下一步需要关联浏览器 trace、服务端收发时刻及系统调度，定位字节交付等待。两轮均启用额外诊断且样本有限，差值不能视为禁用缓存的性能收益。

原始诊断及压缩浏览器 trace 位于 `reports/interaction-network-diagnostic/` 和 `reports/interaction-cache-disabled-diagnostic/`；摘要保存各轮最慢请求及产物 SHA-256。生产缓存策略未变。

本机启动最大值仍为 2729.4 ms，与基线 2744.6 ms 接近；多数启动变快不等于冷进程初始化长尾消失。下一步应优先检查不可变内容重复获取的网络／缓存路径，再评估恢复过程中复用已验证内容的方案；暂不扩大预算、加入自动重试或调整 GPU 同步来掩盖等待。

## 功能验证

- 48 项宿主测试通过，覆盖有界阶段记录、独立累计统计、快照隔离及原有请求生命周期。
- 8 项 presentation、2 项 renderer、8 项 Player Rust 测试通过。像素快速路径穷举全部 65,536 种通道值／透明度组合，与原公式逐字节一致。
- 36 项浏览器用例完成验证：最终 SDK 的完整套件中 35 项通过；存档导入用例修正异步状态等待后定向通过。原测试只等恢复完成，就断言语言事务也已完成；新版测试延迟英语字体，检查恢复期间用户偏好保留，再等待语言事务完成，同时保留存档篡改拒绝断言。没有为此改动生产语言逻辑。
- 新增浏览器检查确认正常菜单操作不调用完整 `Engine.state()`；诊断关闭后仍能进入游戏且不产生阶段记录。原有长文本、滚动、Gate、取消准备、两个结局、语言与设备恢复回归通过。
- SDK／静态发行独立校验、作品两条剧情测试、架构边界、Rust 格式和补丁空白检查通过。

浏览器原始结果保留在 `reports/interaction-browser-gated.json` 与 `reports/interaction-browser-locale-final.json`；首次失败结果为 `reports/interaction-browser-initial.json`。SDK 与发行检查分别为 `reports/interaction-sdk.json`、`reports/interaction-release.json`。

## 复现

```sh
nix develop --command cargo xtask sdk
dist/novelc -p examples/rain-letters resolve
dist/novelc -p examples/rain-letters build --locked --out dist/rain-letters-web
bun run test:performance:hardware --trace=off --grep 'navigation baseline|module scale (shaped-32|capacity-32)|prepared interactions'
```

配置 `CHROMIUM`，无显示环境时指定 `XVFB_RUN`；具体参数见环境报告。诊断字段说明见 [诊断文档](../../DIAGNOSTICS.md#交互与主线程分段计时)。
