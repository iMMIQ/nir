# NIR-0001：Rust / wgpu 叙事播放器中间表示

状态：设计提案 v0.1。日期：2026-09-20。

本文定义的是自有 IR 的建议语义，不是既有行业标准，也不是已实现引擎或性能报告。第一版只有 Web 发行目标，但 VM、时间轴、场景和 UI 投影在 Rust/WASM 中实现，画面由 wgpu 渲染。旧格式解析、转换和作者工具不在范围内。

`example.nir.json` 是虚构内容的结构样例。它不附带实际媒体文件，不能直接作为可玩游戏运行。`check_example.py` 只检查该样例的基础结构和交叉引用，不是完整 NIR 验证器。

## 1. 核心选择

采用“类型化控制流图 + 一条剧情控制流 + 可序列化演出任务 + 显式交互边界”。

IR 表达作品的逻辑与演出意图，不保存 GPU 指令、DOM 对象、Future、闭包或浏览器设备对象。播放、等待、取消、回退和恢复是同一组指令语义的不同执行情形，不另造互不兼容的代码路径。

V1 不引入任意并行剧情线程、共享变量竞争、任意脚本求值或运行时下载可执行扩展。角色、镜头、语音、文字与 BGM 的并行，由演出任务提供。

### 1.1 四种数据不能混为一谈

| 数据 | 内容 | 生命周期 |
|---|---|---|
| Program | 控制流、声明、文本、资源和演出定义 | 内容包版本内不可变 |
| Executable | 解析、验证、符号解析后的索引化运行表示 | 加载后；可重建 |
| Snapshot | PC、变量、等待、任务、场景、交互、随机数等 | 一次播放会话的逻辑状态 |
| RenderPlan / DeviceCache | 可见物体、合成计划、纹理、图集、管线 | 随帧与设备变化；不是存档 |

从 Program 到 Executable 只改变表示，不改变语义；V1 不必设计第二门低层语言。重建设备缓存不得重新执行剧情。

## 2. 包结构与身份

顶层建议包含：format、package、requires、stage、variables、assets、speakers、texts、scene_templates、clips、ui_contracts、read_policies、choices、cues、functions，以及独立的 hints、debug。

内容可分模块加载；引导清单需先提供模块身份、入口与所需能力。不要求下载整个游戏后才能验证并执行首章。跨模块引用由清单描述，模块缺失时在显式边界准备，不能临时解释一段字符串当程序。

身份分为三类：

1. 稳定内容身份：PackageId、FunctionId、BlockId、OpId、TextId、ChoiceId、OptionId、AssetId、NodeSymbol、AnchorId。
2. 运行时身份：FrameInstanceId、TaskInstanceId、NodeInstanceId、InteractionInstanceId。循环调用同一条指令必须得到不同的实例。
3. 宿主相关身份：SessionEpoch、DeviceEpoch、RequestSeq。用来拒绝失效回调；不是内容身份。

发布内容可将符号解析为 u32 索引，热路径不必进行字符串查找。存档必须关联内容版本和可重新解析的地址映射，不能孤立保存某个 Vec 下标。Stable ID 不是跨版本语义迁移的自动保证。

## 3. 类型、表达式与状态分区

### 3.1 数值

逻辑基础类型建议为 Bool、I32、String、Enum、受限集合，以及不透明的资源和任务引用。I32 运算使用 checked 规则；溢出、除零和类型错误产生带指令地址的错误。不采用隐式字符串到数字、真假值转换。

视觉属性可以使用经过有限值检查的 f32。拒绝 NaN 与 Infinity。视觉采样不能被直接读取后用于剧情分支；相同输入保证剧情结果一致，不宣称不同 GPU 的像素逐位相等。

剧情时长使用 u64 微秒，线格式用十进制字符串，字段名带 `_us`。音频循环与采样精度由媒体描述额外约束。程序不得依赖浏览器墙上时间。若确有日期、随机或外部输入需求，必须变为显式输入并可记录。

### 3.2 表达式

表达式是类型化树或已解析的受限表达式指令，不是 JS/TJS/Python 字符串。允许常量、变量读取、算术、比较、逻辑、字符串和受限集合操作。随机数使用独立的 Random 指令，保存指定算法、版本与状态，不隐藏在纯表达式中。

激活包的操作数在进入该终结指令时解析和冻结；重试加载不得重新求随机数。涉及“从当前值开始”的视觉初值，在成组激活时由 CPU 场景状态采样，并写入任务快照。

### 3.3 状态分区

- Frame：函数局部、参数、返回地址。
- Session：剧情变量、调用栈、当前场景、交互和任务；参与读档与回退。
- Profile：已读、CG 解锁等；通过显式合并操作更新，独立声明是否跨回退保留。
- Preferences：音量、字号、减少动态等；不是游戏内容，也不被普通读档覆盖。

若持久解锁影响本轮分支，应在指定边界显式读取并冻结为 Session 输入，不能在每个条件表达式里隐式读系统存储。

## 4. 控制流

每个 Function 包含参数、局部槽、入口 Block 与 Blocks。每个 Block 包含零个或多个不挂起的 Op，以及恰好一个 Terminator。

### 4.1 Op

V1 的 Op 可包括 Assign、Random、DraftPatch、TaskControl、DialogueContinue、ProfileMerge。它们只执行有界的状态变换或登记意图，不等待资源，不直接调用浏览器，并且不回调剧情。

V1 不依赖 SSA。使用类型化局部槽，加确定赋值检查即可。调用返回地址、结果槽与帧作用域必须显式保存。

### 4.2 Terminator

| 终结指令 | 语义 |
|---|---|
| Goto | 跳转到指定块 |
| Branch / Switch | 求值一次，选择一条边 |
| Call | 建立帧，带参数和明确返回位置 |
| Return | 返回；处理帧作用域任务 |
| Activate | 准备一个演出包，原子激活，之后进入 on_started；不等演出结束 |
| Await | 等待任务里程碑或组合条件；成功、取消、失败分别有去向 |
| Interact | 建立一种类型化交互，接收结果后继续 |
| End | 正常结束当前播放会话并清理任务 |
| Fault | 停在明确错误状态，不伪装为正常结局 |

Await 的基础条件是 TaskMilestone、All，以及显式的输入或时间任务。V1 不提供任意条件轮询；不要每帧重新执行有副作用的谓词。

V1 优先实现 All，不实现未定义输家处理策略的 Any/Race。若将来增加 Race，必须定义同刻优先级、输家取消和结果身份。

### 4.3 活跃终结指令不能被重复执行

挂起状态必须记录终结指令地址、解析好的操作数、已分配实例、任务引用、继续边和当前阶段。恢复时从这些状态继续，不重放块前面的 Assign，也不重新启动一次 BGM。

单个运算符原子执行；耗时循环由指令预算切片。切片只用于公平性，不产生新的剧情输入或推动故事时间。持续超预算的无等待循环报告错误，不能卡住网页。

## 5. Activate：准备、成组开始与结束分离

Cue 是有限个类型化效果的包，可以包含 StagePresent、ClipStart、AudioStart、DialogueOpen、TextReveal、Delay 等。

执行过程：

1. 解析操作数，构造 PendingActivation；不改变可见场景。
2. 计算真正的必要资源，并要求达到相应就绪层级。
3. 所有必要资源就绪后，在一个逻辑时刻采样初值、验证所有权、分配任务并提交逻辑状态。
4. 导出任务句柄，沿 on_started 继续剧情。
5. 各成员独立运行，其后由 Await 等待必要里程碑。

背景、语音、字体、转场遮罩等就绪要求不同。就绪不能统一等价于“HTTP 请求已结束”。音频就绪至少包括解码或可调度、输出已解锁；图片就绪可能要求 GPU 驻留；内容必须被语义解析成功才算可执行。

V1 在必需资源准备期间冻结 Story 时钟和与它耦合的媒体调度，UI 时钟继续；预取用于减少这种停顿。将来允许环境音乐在加载期间继续时，必须声明独立时钟与分支隔离，不能悄悄修改该规则。

准备失败时，不得出现半个 Cue 已生效。准备成功后的逻辑提交是原子的，但浏览器的物理出声与显示扫描不是事务；激活后设备错误不能被谎称为从未发生，需要记录任务失败并进入恢复或 Fault。

“同刻激活”保证一个逻辑起点，不承诺显示器和扬声器在同一个采样点输出。宿主需要做时钟映射与延迟测量。

已开始、已提交画面、已完成、被取消、失败是不同的状态。“已提交画面”最多是渲染提交回执，不是玩家确实看见的证明。

## 6. 任务、里程碑与作用域

Task 状态：Preparing → Ready → Running → Finished / Cancelled / Failed。里程碑为带序号的、已锁存事实；等待发生在事实之后也必须立即满足，不能仅等待未来回调。

Finished 表示正常完成。Await 收到取消时走 on_cancelled，不得永远等待，也不得默认当作成功。All 同一时刻若存在失败，失败优先；否则取消优先；全部目标里程碑满足才成功。多个同刻错误按 TaskInstanceId 固定选取主错误，其余保留诊断。

无限循环 BGM 没有自然 Finished，不能等待其自然结束。可以等待 Started、显式媒体标记，或先发停止。静态可证明的无限等待应报错；剩余情况需运行时保护。

作用域可以是 Session、SceneInstance、InteractionInstance、FrameInstance。BGM 通常属于 Session，立绘动画属于场景，语音可属于对白交互。成员可以显式覆盖 Cue 默认作用域；同组新建交互的语音可绑定到该交互。不能有未声明的裸 detached 任务。

作用域销毁需按已声明策略取消任务。函数返回不能悄悄遗留 Frame 任务；应已结束、显式取消或合法转移所有权。节点引用在激活时解析到带代次的 NodeInstanceId，旧任务不能修改同名的新角色实例。

## 7. 调度、时间与确定性

确定性目标：给定同版本 Program、初始 Snapshot 和有序 ExternalEvent 流，得到相同的逻辑状态与宿主意图。资源回调先后次序不是剧情随机源。

外部事件带 session_epoch、request_seq、逻辑接收时间和输入序号。乱序或重复回调按关联表去重；不匹配当前会话的回调直接作废。

Story 时钟使用整数。UI 时钟只影响非剧情界面反馈。Audio 时钟由宿主提供，映射到 Story 时钟；暂停恢复时重建锚点。媒体真正结束与“估算时长到了”应分开，剧情等待的语义要明确。

推进一个时间跨度时，依次处理范围内的截止点、轨道结束和 marker，不能从 t0 一次采样到 t1 后遗漏中间触发。需要剧情响应的 gate 先停止对应任务，由 VM 显式继续后才能跨越。

同一逻辑时刻的有效、已入队用户选择优先于该交互超时；此规则属于语义版本。一个输入事件只能被一个交互消费。新的交互不会继承创建它的点击事件。

模型不追求音频输出与 GPU 像素逐位复现。会改变分支的外部结果需要进入可重放输入流。

## 8. 场景、快照与转场

SceneState 为有身份的逻辑场景，不是 GPU Scene。基础节点类型建议为 Group、Sprite、TextSurface、Mask 与 Camera。SpeakerId 和角色视觉节点分开：旁白可无形象，同一说话人也可有多个视觉对象。

坐标为声明尺寸的虚拟舞台，原点左上、x 向右、y 向下。布局单位不等于物理像素。变换顺序固定为父变换 × 平移 × 旋转 × 缩放 × 负 pivot 平移。pivot 是否归一化由字段类型约定，不能混用；样例使用纹理尺寸归一化 pivot。

绘制顺序用有序父子结构和显式 order，不能依赖 HashMap 遍历。透明物体不能为合批任意重排。Group 必须区分隔离合成后的整体透明度与子节点透明度相乘，两者不能互换。

资源元数据声明色彩编码和 alpha 表示。V1 默认线性光合成与预乘 alpha；需要其他合成语义必须显式声明能力。纹理解码端与 shader 端不能同时或都不做预乘。

### 8.1 提交与转场

Draft 是未提交的逻辑场景差量或快照。StagePresent 在激活时从当前场景生成目标版本，可 cut，也可启动转场任务。

转场数据至少含 root_scope、source_description、target_description、effect、progress、finish_policy、cancel_policy。源侧由激活时的逻辑场景与已解析轨道值冻结得到，不以 GPU 纹理句柄作为唯一来源。

V1 采用“冻结源描述 → 冻结目标描述”的转场。转场期间该 root 的写权限归转场任务；新修改必须等待或显式取消。其他未被包含的 UI 根仍可更新。

含有不可重建媒体帧、反馈 shader 或任意屏幕捕获的效果不属于该保证；作为需声明恢复能力的后续扩展。V1 不宣称任意转场嵌套与动态源侧都可恢复。

重建设备时由两侧描述重新绘制，继续原进度。源、目标与遮罩在转场结束前必须固定引用，不能只因当前场景已指向目标就释放源资源。

## 9. Clip、属性所有权与跳过

Clip 定义时间轴、持续时间、循环、typed channels、keyframes、easing、composition、作用域，以及完成、取消和 skip 策略。

从当前值开始的轨道在激活时捕获初值。轨道运行中不重新读取剧情变量。动画值是时间的函数，而非“每帧累加一点”。

属性由基础值和活动通道共同决定。V1 常规姿态使用一个 replace 写入者；位移震动等使用明确的额外通道或受限 add。任意矩阵 accumulate 后置。

同一属性的两个 replace 默认拒绝。显式 replacement 需先采样旧值，按策略结束旧所有权，再开始新轨道；旧任务产生 Cancelled/Replaced 结果，不能留有悬挂等待。

完成策略可为 commit_end 或 remove_effect；取消可为 commit_current、settle_end 或还原基础贡献。基础值与效果贡献必须分开，移除震动不能把角色本来的位置清零。完成后的终态只写回一次并释放通道，不能永久保留满进度轨道遮住后续修改。

快进不等于把全局 delta 设为无限大。只对标记为可跳过的任务进行终态化，并处理必须发生的中间语义边界。变量、条件和必要逻辑照常执行；非关键音效可以抑制；循环音乐没有可自然跳到的终点。

选项、未读边界、不可跳过的等待会停止快进。自动阅读属于交互策略，不是对所有时间轴加速。静态采样预览不触发 Profile 写入或外部副作用。

## 10. 文本、对白与交互

### 10.1 文本资产

TextDoc 使用结构化 spans：Text、Ruby、Style、ExplicitBreak、Marker 和受限插值。文本不是包含可执行命令的富字符串。

文本格式身份、对白逻辑身份、一次对白出现的实例身份分开。进入对白时冻结插值结果，并记录文本版本与当前语言；回看不能因玩家之后改名而重写之前的历史。

揭示进度保存 span_id 与当前字素簇位置，而不是 UTF-8 字节、字形数量或屏幕行号。Unicode 分段版本固定；字素簇与塑形后的字形映射仍由文字层处理，不能假定一一对应。

语义 Marker 在每种语言里映射到本语言位置，演出不要绑定“第 13 个字符”。缺少 Marker 是验证错误。

全文排版与揭示分离。窗口变化只改变排版，不改变剧情 PC。内容明确分页与视口造成分页也必须分开。V1 切换语言在对白边界生效，避免任意转换句中进度。

### 10.2 对白任务

DialogueOpen 定义 speaker、TextDoc、UI slot、页面替换/追加方式、揭示计划、语音关联和阅读策略，返回 Task<Dialogue>。可与语音和角色动画在同一个 Cue 中激活。

Dialogue 状态至少有 Revealing、AtGate、AwaitingAdvance、Finished。按下确认时：正在揭示则显示到下一个语义 gate；已显示且允许推进时才结束该次交互。打开菜单的操作不能同时推进。

句中演出用 Marker/Gate 表达：揭示到 gate → Await marker → 激活演出 → DialogueContinue → 揭示剩余内容。Gate 不可隐藏为字符串回调；状态必须可存档。

普通等待、必须等待、可由确认跳过的等待应在 reveal plan 中区别定义。自动阅读的默认策略结合文本阅读时间和有效语音完成，但不覆盖内容声明的 hard gate。

### 10.3 选项

Interact<Choice> 返回 OptionId，不是可见列表下标。显示与可用条件在打开时求值一次，并保存 offered snapshot。V1 不让选项列表在玩家点击的瞬间因其他状态变化而重排。

输入携带 InteractionInstanceId 与输入序号，恢复存档时生成新的宿主交互 token。旧点击、重复回调或发给旧选项的事件不得作用于新交互。

选项全部隐藏或禁用必须走显式 on_empty/on_error。限时选项必须有有效默认项与确定的同刻竞争规则；没有默认项不得靠下标零自动选择。

## 11. UI 契约与主题

IR 只引用语义 UI slot 与类型化交互，例如 dialogue.main、choice.main、overlay.phone，以及受限 Props。页面/主题包定义布局与表现。

玩家设置、存档菜单和系统错误恢复属于播放器层，不要求每个剧本重新实现。内容可以选择表现组件，但不能绕过输入令牌、直接写 VM 内存或劫持所有退出入口。

UI 输出 Advance、Reveal、Choose、OpenMenu 等类型化 action；运行时检查当前交互是否允许。UI 投影不修改故事状态。

为验证 Rust/wgpu 路线，正式舞台、文本与交互 UI 可以共用 Rust 布局/文字层及 wgpu 合成；浏览器宿主只承担必要平台接口。无需通过改变 IR 来切换主题。

## 12. 资源、性能提示与设备能力

剧情指令引用 AssetId，不写任意 URL、文件路径拼接表达式或 wgpu Texture。URI、内容校验信息和变体位于独立资源目录。

必须依赖由 scene、text、audio、mask 等类型化描述可推导。Prefetch、温缓存、优先级等属于 hints；删除 hints 后程序仍应逻辑等价，只可能更慢。提示不得绕过必需资源屏障。

不得根据下载竞赛选择故事分支。预加载失败与真正激活失败不同：前者可稍后重试，后者不能悄悄丢失剧情内容。

needs/requires 声明语义能力，例如 stage.dissolve.v1、text.ruby.v1，而不是某个 Rust 函数地址。能力缺失时拒绝加载相关内容，或使用内容明确给定的替代；不能由设备性能偷偷改变剧情。

渲染器可以选用不同纹理变体、合批、脏区域、分辨率或缓存策略；它们不得改变 UI 动作、条件分支和任务完成契约。

## 13. 快照、回退与恢复

Snapshot 至少包括：内容身份与版本、当前地址、帧栈和局部、Session 变量、随机数状态、StoryTick、场景与 Draft、所有活跃任务的参数/初值/进度/所有权、PendingActivation、Await 状态、对白页面和 gate、选项快照、音频意图与位置、历史游标、实例分配计数器。

DeviceCache、GPU 句柄、Promise/Future、DOM、字形图集和宿主音频节点不保存。Profile、Preferences 另存，不被普通回退替换。

快照在 VM 的一致性切点获得：一个同步状态转换前或后，不能在其修改一半时采样。动画运行中，只要 VM 已挂起且任务可表示，就可以保存该时刻的逻辑状态。加载过程中保存 PendingActivation 及冻结参数，恢复后重发准备，不重做前置变量操作。

恢复顺序：检查内容与快照兼容性 → 使旧宿主请求和输入失效 → 恢复纯数据状态 → 重新准备依赖 → 重建画面与音频节点 → 以暂停状态展示 → 用户恢复后继续。

若播放器需要失败时保留当前会话，应先在隔离状态中验证并准备候选快照，成功后再切换会话。不得先破坏当前状态再发现新存档不可读。

音频恢复保存期望媒体位置、循环相位和包络。浏览器物理输出与压缩音频 seek 精度要单独验证；可恢复逻辑不等于逐采样复现。

回退优先恢复检查点，而不是为每条命令编造 inverse。完整事件溯源不作为 V1 必要条件；为测试保存有序输入和可观测 trace 即可。

ProfileMerge 推荐 V1 只允许单调、幂等的解锁/已读合并。对外网络提交、任意插件副作用后置。不能承诺通过保存一个请求 ID 就获得跨服务严格 exactly-once。

## 14. 线格式、版本与安全

V1 可以 JSON 作为规范化交换表示，Rust 使用明确 tag 的 enum 与类型化结构。输入先做大小/深度/数量限制，再解析与验证，再构造可信 Executable。不要在每帧解析 JSON 或用 Value 查字段。

语义版本、内容版本、存档格式版本、扩展 ABI 版本分别管理。未知核心 opcode 必须拒绝；只有预留的非语义 metadata/hints 字段可以忽略。major 不兼容直接拒绝；minor 增量依赖显式能力声明，不自动视为可向后忽略。

紧凑发布编码以后根据数据测量选择，不能把 Rust 枚举内存布局、Vec 指针或默认枚举序号当稳定文件 ABI。编码变化必须保持规范化后的逻辑语义等价。

限制资源数、图片解码尺寸、文本字节与簇数、嵌套深度、调用深度、每步指令数、活动任务数和持久化快照大小。纯声明式输入同样不能默认可信。

## 15. 验证器应拒绝的问题

### 静态与包级

重复身份、缺失引用、类型错误、未初始化局部、无效控制流、缺能力、文本 Marker 缺失、无效 keyframe 顺序、负/溢出时长、自然等待无限循环、错误 task milestone、可证明的资源与属性冲突、无出口的空选项、非法作用域转移、超限数据。

### 运行时

表达式溢出、动态无效节点、资源不可用、实际所有权冲突、循环预算耗尽、已销毁任务访问、错误交互令牌、失效回调、设备丢失，以及无法静态证明的等待问题。

不能声称静态分析能发现所有死循环或死锁；需要运行时预算和结构化等待约束。诊断至少含 error code、模块/函数/块/指令、任务实例、资源与 source_ref（若提供）。source_ref 只用于定位，不进入执行。

## 16. V1 一致性测试

| 用例 | 必须满足的性质 |
|---|---|
| 同一输入重复执行 | 逻辑 trace、变量、选择一致 |
| 正常逐步跑与跳到时间点 | 不漏掉必须经过的 marker 和逻辑边界 |
| 普通播放与合法快进 | 分支与关键终态一致；允许声明的声音/进度差异 |
| 动画 37% 时存读档 | 参数、捕获初值、进度和所有权恢复，无重复起播 |
| Activate 准备中存读档 | 不重复前面 Assign，不重复创建有效任务 |
| 转场中设备重建 | 从逻辑源/目标描述恢复，不需保存 GPU 截图 |
| 选项界面收到旧点击 | 事件被拒绝，不选择新选项 |
| 下载顺序交换、开关 hints | 剧情结果不变 |
| 同一属性动画被替换 | 旧等待得到明确取消结果，不悬挂 |
| BGM 循环结束等待 | 可证明无自然结束时验证失败 |
| 字号、屏幕改变 | 重新排版，不改变 PC 与已选结果 |
| 更换主题 | 交互结果和故事 trace 一致 |
| 不兼容快照恢复 | 当前有效会话保持不变并给出诊断 |
| 旧请求在读档后完成 | 不污染新会话 |

这些是将来实现需要通过的测试，不表示本设计包已经执行了播放器测试。

## 17. Rust 模块边界与第一版范围

建议 crates：nir-schema、nir-validate、nir-runtime、nir-scene、nir-text、nir-ui、nir-wgpu、nir-platform-web。schema/runtime/validate 不依赖 wgpu 或 web-sys；只有平台层认识浏览器对象。

优先完成控制流、纯表达式、Cue 激活、Await、sprite/group、cut/dissolve、少量 scalar/vector 动画、基本混音总线、结构化对白、选项、快照和诊断。

推迟任意并行脚本、多媒体反馈型转场、任意动态扩展、网络副作用和通用复杂自定义控件。扩展所需边界现在保留，不等于第一版实现所有能力。

实现顺序：冻结基础语义与样例 → 无 GPU 核心解释器与一致性测试 → wgpu 场景/文字/UI 投影 → 真实 Web 资源和音频适配 → 性能测试。无 GPU 测试是为了验证模型，不替代最终的 Rust/wgpu 技术验证。

## 18. 尚需用原型验证的设计参数
