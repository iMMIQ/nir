# NIR-NEXT 实施计划

状态：实施中，阶段证据见 [实施进度](NIR-NEXT-PROGRESS.md)。初版制定日期：2026-09-28；代码基线：`8c44ace`。依据用户提供的《NIR-NEXT：迁移表达能力与语义增量方案》，对照当前仓库细化。本文不代表新能力已经实现或验收，不改写原六份规格。此前 `EXPERIENCE-SEMANTICS.md` 为探索草案；执行顺序以本计划为准，具体格式仍须在对应阶段冻结。

## 1. 目标与执行边界

保留唯一剧情控制流，扩展现有任务、有限界面组合、阅读边界和类型化服务，使新导入器主要完成语义映射。不能把“原作兼容”收缩为固定模板换皮，也不通过任意源脚本执行来绕开设计。

每个功能按“契约与中性样例 → 格式/验证 → 执行与恢复 → 后端 → 导入映射 → 实际播放验收”贯通交付。公共仓库只存中性样例；原包、原版行为记录及含来源信息的报告保留本地忽略目录。

本计划不授权运行未知原版可执行文件、引入原素材、提交或推送。原版对照条件不足时使用明确标注的文档/源码证据，保留未验证项，不能因此停止其他可独立推进的开发。

## 2. 已核实的实现差距

| 提案依赖 | 当前实现 | 对实施计划的影响 |
| --- | --- | --- |
| 生命周期与 All | Core 已有 Running/Finished/Cancelled/Failed，Await 失败优先、再取消、再全部完成 | 复用终态；Replaced 等优先作为终态原因，不增一套 TaskState |
| Clip 与循环 | Clip 仅 scene node 的 x/y/scale/opacity、单区间 linear/smooth；没有循环字段 | 提案所说“现有循环 Clip”不能直接使用；先做静态指示器，动画另加有限契约 |
| 场景转场 | StagePresent 仅 scene/duration，任务持有 source/target | 扩参数、根范围和闭包，不另建转场任务体系 |
| 音频 | Audio 只有 asset/bus/looped；直接停止，没有每事件 gain/包络 | 音频实例、终态原因、gain 和停止契约先于菜单音乐 |
| 暂停与后端 | Player 有独立暂停 owner；Web/Windows 音频命令仍有统一暂停语义，Windows sink 按 bus 设置音量 | 增加 owner/time-domain 路由；不能让菜单暂停冻结菜单自己 |
| 图片菜单 | 背景、矩形按钮、hover/locked 图片、Profile guard、少量动作 | 增量加入组合/局部数据/服务绑定；旧配置保持可用 |
| 回想 | ImageMenuEntry 为函数入口，现有入口不能当作完整隔离 Replay 服务 | 单独建立初态、Profile/保存政策、冻结和返回事务 |
| 阅读 | Dialogue/Gate、字素揭示、视口翻阅、已读快进已有；Auto 看活动 Voice 总线；偏好没有字速/自动等待 | 先补语义边界和具体语音实例关联，再开放策略与设置 |
| 存储 | 已有独立 SaveJob、槽 revision、候选恢复、迟到结果校验 | 自定义 UI 只能调用服务，不重新实现事务 |
| 版本/能力 | source=1、runtime=2、snapshot=1；已有 requires/CAPABILITIES；编译器写入全部能力 | 复用声明和校验，改为实际使用闭包；不预先整体升版 |
| 恢复 | 快照检查已强依赖 Task 时长/状态/里程碑等不变量 | 新 owner、组合游标和局部状态必须同时改 restore 验证，不能只扩 DTO |

代码锚点：`nir-format/src/lib.rs`，`nir-core/src/{vm,validate,restore}.rs`，`nir-player/src/lib.rs`，`nir-presentation/src/{lib,reading}.rs`，`nir-engine/src/lib.rs`，`nir-compiler/src/{project,import/livenovel}.rs`，`nir-platform-web/host.js`，`apps/player-windows/src/desktop.rs`（均相对仓库相应 crates/apps 目录）。

## 4. P0：先固定需要实现什么

建议拆成两次可评审改动。

**P0.1 基线与验收样例**

- 建立需求 ID N01–N10，对应方案需求表；另设 R01–R06 保留已修复六项回归。
- 保存旧格式合成 Program、旧图片菜单、Gate/长文、音频和保存场景的基准输出与语义 trace；运行现有检查建立本轮基线，不沿用历史测试数量作为新成绩。
- 创建三个原创中性 fixture：带 Gate 的对白/语音/转场；锁定回想菜单；页签设置/存档/历史页面。未实现片段以行为期望描述，不伪装为可编译格式。
- 来源样例至少两个引擎家族。优先现有 LiveNovel 适配和 KAG 的小型固定子集；第二来源不要求先实现完整导入器。记录精确版本/源码提交/参数/证据方式；无原版运行证据时标“待认证”。

**P0.2 最小契约记录**

- 冻结目标身份、任务结果原因、时间域、源页边界、输入消费、页面动作白名单和 Replay 策略的状态表。
- 数量上限覆盖 View 元素/局部数据、表达式深度、计划深度/叶子总数、可见集合、并发 UI 音频、文本输入长度；结合当前 MAX_TASKS 等约束制定数值，拒绝无界递归与零时长无限循环。
- 列出 source/runtime/content/snapshot/preferences/schema/host protocol 的逐项影响。只有实际变化的格式升级，旧文件缺省行为不改。

完成证据：能力账本、版本矩阵、fixture 清单和基线测试记录。此阶段不需要建立通用框架。

## 5. P1：复用效果机制，明确所有者

**P1.1 任务结果和播放实例**

保持既有四种 TaskState；新增必要原因，区分自然结束、显式 Finish、停止、替换、scope 退出和失败。TaskRef 在提交时解析到实例，回调携带会话/实例/代次；Web 的 ended 和 Windows sink 结束分别分类。必须定义自然结束与 stop 同轮到达的顺序及幂等规则。

修改范围：format、Core task/input/intent、restore、Player command/event、两个宿主。验收：重复 stop、旧 ended、同名新声轨、自然结束早于淡出不会误结束新实例；旧 Await 的分支选择保持不变。

**P1.2 类型化目标与共享求值**

将 scene node 的目标解析扩为经过白名单验证的 SceneNode、DialogueRoot、ViewElement、AudioInstance 等域；按域限定属性。共享插值、完成/取消政策和结果结构，状态存储仍由各 owner 持有。先在现有库内部抽取纯机制；没有依赖图理由不新增 crate。

Core 只持有故事语义，Player 持有瞬态系统页效果；不把 Core 变成操作浏览器菜单对象的反射系统。跨 owner 操作通过显式协调，不能随处 Await 任意时钟上的任务。保留旧 Clip 编解码/归一化路径。

**P1.3 分时钟暂停与恢复**

建立 Story 与 foreground-UI 的推进和音频暂停路由；保留独立暂停所有权。系统菜单暂停 Story，自身 UI 时间继续；后台/设备恢复停止相应域。命令明确作用于 owner/实例集合，不再只靠一个全局 audio_paused。

验收：嵌套暂停不互相解除，菜单退出不等待已冻结的 Story 动画；恢复锚点不重放动作；取消后活动请求和租约回归基线。Web/Windows 同时接入，未验证的后端明确标记。

## 6. P2：完成第一个端到端剧情案例

按以下四个独立改动推进，各自包含格式、验证、恢复、后端、导入与测试。

**P2.1 音频增益和淡出停止**

区分事件 gain、作者通道状态（只有样例需要时引入）、玩家 bus gain 与包络；默认不加 duck 等尚无消费方的字段。停止带时长，复用既有任务结果/Await。底层可共享属性轨道，但简单 fade-stop 不依赖 P5 通用 Sequence。转换器停止将事件增益烘焙入 PCM。

定义 FadeStop 自己的完成结果与被停止 Audio 的终态；目标先结束、重复 stop、Finish、scope 强制退出都有明确政策。替换默认先准备再提交；源先停后加载需显式映射。恢复保存实例、offset、当前增益和剩余进度。

**P2.2 阅读边界与输入**

区分源交互/源页/布局视口页，建立对白与具体非循环语音实例关联，支持页内 Gate 后绑定。旧作品仍使用旧策略；新导入明确选择翻页停止、语音后等待或并行等待。字速和自动等待作为独立偏好，当前实例的生效时点明确。

共享语义输入路由，Web/Windows 映射物理事件。实现背景推进、临时隐藏、Ctrl held、失焦释放和焦点优先；隐藏的暂停/音频策略按来源显式选择，不能未经证据一律暂停音乐。不能穿越硬 Gate、选择或误将视觉翻页当源翻页。先补所有对白布局的静态就绪提示。

**P2.3 消息框和文字目标**

复用属性效果控制消息根；区分背景、文字和整体 alpha，用户隐藏是额外显示掩码。补单层阴影和现有 FontPlan 配置映射。先覆盖脚本显隐动画及中途恢复，再做装饰循环指示器；如需帧序列/循环，独立提交其正时长与资源限额契约。

**P2.4 遮罩转场**

先做场景根的方向/阈值遮罩，随后沿相同根目标接口支持消息/UI 根。规范冻结输入、通道、极性、采样、软边、端点和合成空间；不将源 vague/ramplen 直接等价。渲染 packet、两个 GPU 后端、依赖收集和联合预算一起调整。动态/live 输入另列能力，不暗中当 frozen。

P2 完成门槛：案例 E1 在门内、转场中、淡出中分别保存/恢复，trace 不重复逻辑或一次性音效；真实音频节点/原生输出路径记录停止原因及包络；遮罩关键进度做像素对照。没有源实机证据时不能标原版表现精确。

## 7. P3：有限页面组合与系统服务

**P3.1 View 静态组合及旧菜单适配**

新增有序 Image/Text/HitRegion、有限 Group/裁切、Button；固定坐标/锚点优先，增加必要的文字流式测量。旧 ImageMenu 降为同一路投影或保留经过差分验证的兼容路径，不能长久维护两套不同命中语义。绘制、裁切、命中、焦点、辅助语义共享相同变换。

**P3.2 局部状态和纯绑定**

新增有界局部 Bool/I32/有限字符串等必要类型、params、只读 Player 模型和明确导出的故事数据。先满足页签/选择槽，避免通用全局 store。动作仅可有限赋值、启动所属效果、提出类型化请求或返回结果；不允许循环派发、任意 IO 或写剧情变量。布局求值反复执行不得产生副作用。

**P3.3 值控件、集合和服务绑定**

加入 Toggle/Range、稳定 key 的可见集合窗口和模板；服务模型按需提供 Preferences/SaveSlots/History/权限。每次动作带 ViewInstance、ControlId、模型 revision 和服务请求身份；服务侧复查，失效点击被消费，不能穿透。

复用现有 SaveJob/LoadCandidate，加入必要的确认令牌和状态投影。历史重放语音、截图槽预览等在代码核实后列独立增量，不因方案例子出现就当成现成功能。基础页先复用当前槽数量，不同时扩存储容量模型。

完成门槛：E3 的三个页签、音量/字速、选槽保存/加载和历史窗口可运行；保存确认与 Back/Load 交错正确；大量合成项只实例化有界窗口，活动资源不随总条目无界增长。覆盖键盘/触摸/窄屏/字体放大；文本输入控件若本阶段不交付，IME 验收移到 P5 并明确状态。

## 8. P4：回想服务与页面媒体

**P4.1 页面效果挂接**

在明确的提交/焦点改变/动作接受/关闭边界触发效果。Preparing 不播放 enter 音效；Close 锁定旧输入并等待有限 UI 效果，故障/紧急退出可以取消。循环音乐不加入要求自然完成的等待集合；恢复投影不重播点击音效。旧页、候选页和退出页共享预算。

**P4.2 Replay 事务**

显式入口/初态/Profile 写入/保存政策/返回政策。只运行一个 Core：先冻结原会话描述，准备候选，成功后切换；失败保留当前会话和页面。默认隔离方案不改变旧 ImageMenuEntry 的既有行为，新 Replay 要求明确声明。

冻结原会话计入快照/内容预算，不把整作媒体永久 pin；返回时在候选中重新验证/准备原会话，失败保留可恢复出口。规划嵌套限制、返回页局部状态与音乐返回政策。共享变量写回或 sleep/awake 类语义须另有来源规则，不默认为 Replay。

完成门槛：E2 全流程、锁定复查、连点、候选缺资源/预算失败、回想结束/手动返回和 Profile 隔离；旧入口及六项修复均不退化。

## 9. P5：有证据才增加组合与故事内交互

**P5.1 Sequence/ParallelAll**

必须用“主 VM 等对白时，另一条先位移再淡出链仍前进”的样例证明不能仅靠已有 Activate/Await 编译。组合仍是 Task，禁止 Assign/Random/Call/存储等剧情或服务副作用。

激活时冻结参数与全部有限资源闭包，子项启动时捕获当前属性。定义子项 ID、游标、结果归并、取消、Finish 对未执行 Stop/里程碑的处理；零时长有限链计入执行预算，禁止无限零时长循环。已完成副作用不回滚。资源闭包超预算明确失败，不偷偷沿途下载。

**P5.2 故事交互与快照**

复用 Interact 控制流扩展类型化结果；增加故事内 View 的语义局部状态与效果快照，系统页 hover 等瞬态不进入。选择原创物品检查/密码面板之一，值变更最终由唯一 VM 接收结果后写剧情。文本输入若采用密码案例需同步实现 IME、字符/长度限制、取消和焦点消费。

完成门槛：并行链中途、局部状态改变后存读档/回退不重复音效或动作；第二来源案例复用相同核心；无限循环媒体与 All 的不可完成组合被诊断。若 P5 证据不足，保持待实施而非为了完整度添加协议。

## 10. P6：兼容与发行闭环

ImportReport 分开记录映射等级与证据强度：exact/adapted/approximate/unsupported 是行为结论，文档/固定源码/原版实机/跨后端是证据。报告记录规则 ID、源版本、规范行为、目标能力、允许近似的位置和未决项，公共记录不含私有路径或正文。

未知动态行为不能按死代码丢弃；unsupported 在所选发行闭包内阻止产物被声明可兼容，或明确排除内容并改变声明。近似必须有作者显式配置，不仅输出一条易忽略 warning。

requires 根据实际指令、配置、绑定和资源闭包推导；验证器拒绝缺声明和不支持组合。每个后端能力只有执行、恢复和真实后端验收通过后才广告。SDK 锁、schema、独立 CLI、release verify/stage 等随阶段升级；不替换旧发行及其运行时，不承诺跨发行存档迁移。

最终运行原有实包完整主线与全部入口，并加入 Auto、held skip、隐藏/菜单切换、演出中保存等路线。至少一个第二来源通过小型端到端转换，证明通用能力不是现有导入器的私有分支；不因此宣称完整支持该引擎。

## 11. 统一验收与完成定义

| 层 | 必须记录的证据 |
| --- | --- |
| 格式/编译 | 正负 fixture、引用/属性/权限/范围校验、旧格式行为差分、确定构建及能力推导 |
| Core | 0 时长、同刻终态顺序、Gate、Cancel/Finish/Replace/scope exit、快照结构校验 |
| Player | 准备失败/重试、独立暂停、候选取消、旧输入/回调、服务事务独立性 |
| 实际平台 | WebGPU、WebGL2、Windows 实际后端各自标记；像素/音频/真实输入与恢复 |
| 资源与发行 | 旧默认预算、请求/租约计数归零、列表有界、独立 SDK 构建导入发行 |
| 来源语义 | 版本固定的行为表和对照记录；逻辑、表现、人工试听分开结论 |

测试阈值在 P0/P2 先用中性样本定义：逻辑与身份要求精确，像素容差分后端，音频逻辑时间与设备输出延迟分开统计。先建立基线再制定性能门槛，不凭空承诺毫秒数或物理内存上限。

Windows 真机/音频设备或硬件 WebGPU 不可用时，将对应门禁列为“待验证”，不以交叉编译或软件 WebGL2 代替。其他平台的实现可继续；全平台能力发布必须等各自门禁满足。

每个改动完成需同步恢复校验、资源依赖收集、schema 和实际使用示例；不留下仅能序列化但无法执行的公开能力。文档变动本身不要求跑全套运行测试；开始实现后按影响范围执行现有 Rust/Host/Browser/Windows 检查，再在阶段出口执行集成路线。

## 12. 首批实施清单

1. P0.1：重跑基线、建立 N01–N10/R01–R06 账本与三个中性案例。
2. P0.2：冻结实例/结果/时钟/版本矩阵与数量限制，记录旧语义。
3. P1.1：播放实例和终态原因贯通 Core、Player、Web、Windows。
4. P1.2/P1.3：类型化目标纯机制、owner 路由与分域暂停。
5. P2.1：事件增益和淡出停止完成首个可播放增量。
6. P2.2：明确阅读边界、语音关联与玩家阅读操作。

首批不实现完整页面语言、通用事件总线、动态插件 ABI 或抢占式剧情线程。自定义 UI 和回想隔离已有明确后续交付，不因近期子集而删除长期表达目标。真实异步剧情抢占、插件 wipe、共享临时场景和实时小游戏逐案收集证据，必要时单独设计窄能力。
