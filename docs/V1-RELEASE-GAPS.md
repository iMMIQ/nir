# 面向可发行首版的设计差距

最初核对基线：`8042ccd`，2026-09-24。本页已随 M4.1/M4.2 实现更新；本轮验证记录见 [M4 发行与桌面渲染](M4-RELEASE.md)。

## 判断标准

首版目标是：作者使用独立 SDK 完成作品、验证与构建；作品部署到 HTTP(S) 后，玩家能在声明支持的平台完整游玩、保存恢复；作者能安全发布更新和回滚，旧会话与存档有明确处理途径。

性能测量用于发现会阻断这些流程的问题。通用增量构建、更多预取、优化执行格式以及进一步压缩包体，不应优先于缺失的发行流程和平台兼容能力。

六份文件包含首版要求、推荐方案和明确后置能力，不能将所有段落都视为首发阻塞项。也不能将此前缩小交付范围的说明，当作文档原定首版要求已完成。

## 已具备的首版基础

- 独立 CLI/SDK、作品初始化、精确 SDK 锁、检查、剧情用例、构建与监听预览；有不依赖 Cargo 的独立 SDK 验证。
- 多模块、按需加载及驱逐，结构化对白、选项、两条结局，基本图像/动画/转场、混音、自动阅读和回看。
- 简中/英文 UI 与正文独立选择、翻译契约与修订、字体子集及覆盖检查。
- 存档事务、修订冲突处理、导入导出、候选恢复和设备重建；有失败保留当前会话的测试。
- 静态内容寻址产物、会话固定发行、对象校验、gzip、来源许可；本地根路径和子路径最终产物测试。

因此，当前已经具备受限平台作品的可玩基础；仍不足以宣称六份设计里的 Web 首版发行契约全部落实。

存档政策不要求首版自动迁移任意剧情改动。允许拒绝不兼容存档，但需要保留数据、说明原因并提供可执行的恢复途径；解除 release 校验不能替代兼容设计。

正式发布也不要求先开发通用云发布平台。可先提供作者可用的校验工具、托管配置与操作流程，完成一次真实晋级/回滚验收。

## 有设计差距，但需按首版声明安排

- **文本与演出**（NIR-0001）：Ruby、NVL、更完整的变换和 Clip、隔离组混合仍缺。基本 ADV 所需的对白、选项、图像和转场已有。要建立逐项能力与一致性用例，不能用测试总数声称整份规范通过；也不必先实现所有高级演出才能发布基础作品。
- **国际化**（NIR-0003）：独立配音语言、格式化区域、本地化媒体与更完整的回退仍缺；繁中/日文及复杂文字系统未正式验收。文档允许有限正式语言集，因此已验收的简中/英文可以作为明确首发范围；配音与其他语言能力不能超出实际实现宣传。
- **作者资源与主题**（NIR-0006）：现有 PNG/WAV、字体编译、受限主题可以完成基础作品；通用资源处理、更多主题页面和素材助手继续有价值，但不是所有作品的发行前置条件。
- **一致性覆盖**（NIR-0001 §16）：将规范用例逐条关联已有 Core/Player/浏览器测试，补缺项。重点是普通播放/快进、准备中或演出中恢复、语言/主题不改剧情、陈旧输入和回调拒绝，而非仅增加测试数量。

## 不作为当前首发主线

- NIR-0006 §15 将试玩发行检查列入 P1；可以先完成 `full`，但不能宣传已支持试玩闭包。
- NIR-0003 明确将 PWA/离线列入 P1。
- NIR-0004 的通用增量构建、紧凑模块、高级优化需要后续推进；字体已有专用缓存。
- Worker 仍是 NIR-0005 的目标架构；NIR-0002 允许结合实测决定全栈默认启用。当前若没有阻断游玩的主线程问题，不以完整线程迁移作为作者首次发行的前置条件。
- M3 的 PSS 缓慢上移、测试循环变慢及偶发恢复离群值保留为已知风险。若复现为崩溃、持续资源耗尽或真实交互失效，则升级为发行阻塞；当前证据不足以把它们排在所有产品缺口之前。

## 里程碑与下一阶段

1. **M4.1：发行与存档安全**。本轮交付：dev/release 边界、托管校验、晋级/回滚、独立发行存档和历史续玩入口。
2. **M4.2：WebGL2 与桌面验收**。本轮交付：标准双后端包、启动回退、设备恢复和桌面 Chromium/Firefox 测试矩阵。
3. **M4.3：作者独立交付验收**。下一步补用例预览和开发实例隔离；用独立多章节作品完成两条路线、语言切换、作者修改、打包、上线、更新及回滚，验证不依赖引擎源码或手工修改引擎。

这些里程碑是项目实施顺序，不是六份设计文档已有的编号。随后按真实作品需求安排演出/国际化扩展及性能工程。
