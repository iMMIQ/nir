# 音频实例、增益与停止

当前新增能力为 `audio.gain.v1`、`audio.stop.v1` 与 `audio.gain-tween.v1`。仍使用既有 Effect/Task、Activate/Await、scope 与准备提交，不增加另一条剧情执行流。

## 播放与音量

`Audio` 的 `gain` 为有限的 0–4，缺省 1。音频素材保留单位增益 PCM，实际输出为事件 gain × 玩家总线音量 × 实例包络。设置界面改变总线音量不能覆盖正在进行的包络，也不能释放菜单/后台的暂停所有权。超过满刻度的混音仍可能在设备输出端削波，事件增益并非自动限幅器。

## 淡出停止

```json
{
  "id": "music_stop",
  "scope": "session",
  "effect": {
    "type": "audio_stop",
    "target": "music",
    "duration_us": "500000"
  }
}
```

这是 Cue 中的一项 EffectDef。target 引用已建立的 Audio 句柄，在激活提交时绑定具体任务实例；随后同名句柄指向新声音也不改变此绑定。duration 为十进制微秒字符串，范围 0–60 秒。target 必须为同模块的音频任务，不能引用停止任务自身。

停止任务从目标当前包络线性淡至 0，期间目标 Audio 保持 Running 并保留资源；到期停止声音。等待 `music_stop.Finished` 表示停止操作完成；原 Audio 为 Cancelled，不能据此声称自然播完。

| 事件 | 结果 |
| --- | --- |
| duration=0 | 同次激活提交完成停止 |
| 目标提前自然结束 | Audio 保持 NaturalEnd，停止任务立即 Finished |
| 对已终止实例停止 | 停止任务立即 Finished，不复活声音 |
| 另一个停止任务仍拥有同一实例 | 拒绝为所有权冲突；候选提交回滚 |
| Cancel 停止任务 | 提交当前包络值，原声音继续，不恢复为 1 |
| Finish 停止任务 | 立即执行终点，停止原声音 |
| 直接 Cancel/Finish 原 Audio | 原声音立即结束，所属停止任务同步收尾，原因不冒充自然结束 |
| scope 退出或新会话 | 沿原 scope/会话清理硬停止，不等淡出阻塞清理 |

停止任务不能引用尚未建立的音频；同 Cue 内顺序建立的前一项 Audio 可以被随后 Stop 引用。未知目标类型、跨模块目标、非法时长和缺少能力声明在验证时拒绝；活跃实例和冲突在原子提交时再次检查。

## 实例增益补间

```json
{
  "id": "swell",
  "scope": "session",
  "effect": {
    "type": "tween",
    "target": { "type": "audio_instance", "task": "sample", "property": "gain" },
    "to": 0.25,
    "duration_us": "800000"
  }
}
```

`audio.gain-tween.v1` 在 `tween.target.v1` 的共享轨道上加一个 `audio_instance` 目标：把一个已建立 Audio 实例的包络（0–1 的乘子，叠加在事件 gain × 总线音量之上）在有限时长内线性补间到 `to`。包络不是 PCM 预乘，也不改变播放位置与生命周期——声音始终 Running，只在设备包络节点上排入一条线性 ramp。只允许 `easing = linear`（设备每次只渲染一条线性段，非线性行为由作者自行分段表达）；`to` 必须在 0–1。

目标必须是同模块的另一音频任务（不能引用补间自身，目标的全部定义都得是 Audio），与 `audio_stop` 共享互斥的包络所有权：同 Cue 内两个包络写者在验证期以 E_OWNERSHIP 拒绝，运行中重复占用在原子提交时回滚。补间完成提交终点值并 Finished，声音留在该音量继续播放；Cancel 提交设备时钟已到达的当前值（设备领先剧情时钟时以设备值为准，与淡出停止同一规则），迟到的旧 owner 观测不能再移动它。飞行中存读档保存捕获值、目标与剩余段，恢复从剩余段继续，不从单位增益重来；设备包络检查点（owner/elapsed）同样适用于补间 owner。

## 前奏与指定循环区间

`audio.loop-region.v1` 为循环 Audio 和菜单音乐增加可选的 `loop_region`：

```json
{
  "type": "audio",
  "asset": "audio.theme",
  "bus": "bgm",
  "looped": true,
  "loop_region": { "start_us": "2000000", "end_us": "42000000" }
}
```

首次从素材起点播放至 end，随后重复 `[start, end)`；start 之前的前奏只播一次，end 之后的尾部不进入循环。边界是十进制微秒字符串，必须满足 `0 <= start < end <= 素材时长`；非循环音频声明区间、缺少能力及越界均被拒绝。延迟加载的内容在音频 catalog 到达后补做时长校验。菜单音乐使用同一字段与能力。

Web 按解码 AudioBuffer 的采样率、原生按解码 PCM 的采样率，把边界四舍五入到最近完整采样帧。舍入后空区间或超出实际缓冲同样拒绝；立体声边界不会拆开同一帧的声道。浏览器重采样可能在尾端少一个输出帧：仅当作者 end 等于已验证素材时长且恰超出实际缓冲一帧时，Web 将 end 解析为实际缓冲尾端。内部区间、缺少时长身份、两帧及以上截断仍拒绝，不补静音或修改作者时间。Web 在 AudioBufferSourceNode 上设置 loopStart/loopEnd，原生在连续 Source 中绕回主体；不依赖 JS 定时器反复创建声音。

原生每个声音在进入 Sink 前保持一个持续的设备采样率转换器，随后才应用设备时钟包络；循环和队列分段不会重置重采样相位。每个 Sink 只装一个固定格式的声音，先安装声音、音量和暂停政策，再以该格式接入 mixer；不使用空队列的默认 48 kHz 单声道信息启动转换。原生混音输出测试覆盖 44.1/48 kHz、100 次非整比循环、读档起点，以及单次 MP3 起播和尾部，不依赖音频硬件。

存档保存包括首次前奏在内的累计设备位置。恢复位置小于首次 end 时仍在前奏/首轮，超过 end 后映射到主体区间，不重播前奏。缺少字段的素材保留原整段循环行为。作者负责选择音乐上自然衔接的区间；播放器不统一裁剪、补静音或交叉淡化，继续采用 MP3，无 WAV 回退。

`tests/nir-next/audio-loop-region.spec.js` 对中性 MP3 在 44.1/48 kHz 上离线渲染前奏和 100 次主体循环，并逐采样比较实际输出与独立计算的预期；另验证 Worker/主线程宿主的菜单保存及读档恢复。离线输出证据不代替 Android 音频设备、系统打断及长时间真机验收。

## 恢复和后端

Web 对正在调度、未停止且玩家增益大于零的声音检测输出状态。若对应 AudioContext 非 running，同时该域/总线没有播放器暂停政策，显示“点击恢复声音 / Tap to resume sound”。初次解锁失败和运行中浏览器打断都适用。没有声音、主动静音、菜单挂起 Voice/Sfx 或后台暂停不产生提示；取消静音后若仍缺输出会再次提示。

等待输出使用独立的逻辑屏障：冻结 Story、文字揭示、自动计时和剧情输入，不强行挂起其他已工作的声音，也不重建或停止受阻 source。Engine 持有屏障，Worker 与主线程宿主使用同一逻辑；解除屏障只释放自身，不能解除菜单、后台、显式暂停或加载。后台期间隐藏提示，回到前台后按实际输出重新判断。

恢复按钮只请求设备 resume；在等待状态下画布点击和 Enter/Space 也只恢复声音，不推进当前交互。拒绝恢复保留提示；成功后保留原声音实例/位置与 Auto 周期，宿主与 Worker 丢弃等待期间的 Story 时间。按住快进的释放仍可送达，不能因输出等待留下按键状态。四个设备状态事件合并为一次宿主唤醒，屏障 RPC 使用保留的控制容量。此行为由中性 MP3、真实浏览器上下文加权限失败注入验证，不代表 Android 设备系统打断已经验收。

页面媒体、内容和语言资源屏障只暂停 Story 逻辑推进及候选提交，已启动的 BGM、语音和音效继续按音频设备时钟播放。音频资源解码就绪不等待 AudioContext.resume()，设备解锁仍在用户手势中独立执行。菜单、设置、历史和存档界面只冻结 Story 逻辑：Story/BGM 继续播放，Story/Voice 与 Story/Sfx 由独立总线所有权暂停；若作者声明了菜单音乐，则保留并暂停 Story/BGM，菜单音乐失败或退出后释放这一所有权。后台、显式暂停、阻塞故障、设备恢复及读档后暂停仍挂起整个相应音频域；多个暂停所有者分别释放。翻页是否停止语音由作者任务作用域和导入规则决定，不由加载屏障决定。

加载期间仍采样设备播放位置和包络检查点；不把这些观测换算为 Story 补时，不推进打字机、转场、自动阅读或 VM 指令。已有设备包络可以在加载期间完成其调度段，逻辑任务随后按原契约收尾。读取快照使用观测位置，循环声音不因下一页准备而重建。浏览器音频渲染与普通 JS Worker 是不同执行机制；当前 Web Runtime/Asset Worker 迁移状态及后续验收见 [执行域与线程边界](WEB-EXECUTION.md)。

快照 v2 保存终态原因、停止目标实例、捕获值、包络基值、任务 elapsed、可选的设备播放位置 audio_position_us 与停止任务的 audio_device_elapsed_us。恢复验证引用、任务类型、单实例所有权及进度，并从剩余包络继续；不重新从单位增益开始。重复/迟到的音频结束回调不能改写已停止任务或新声音。

设备位置是观测元数据，不是第二份剧情时钟。宿主在动作提交和 Tick 前采样活动声音；Player 按时间域/会话过滤，Core 只接收运行中的 Audio 实例，拒绝重复任务和超限批次。观测不执行指令、不推进 elapsed 或里程碑。保存/恢复优先使用最近的设备位置；旧快照缺字段时沿用 elapsed。循环音频保存累计位置，整段循环起播时按素材长度取模；声明 loop_region 时保留首次前奏，并按主体区间映射恢复位置。后台暂停由域所有权决定，菜单暂停由总线所有权决定。此字段仍属于尚未发行的快照 v2，不要求作者声明新能力；新宿主和 WASM 必须来自配套 SDK。

这解决设备与剧情时钟推进不同步造成的 seek 偏差；菜单中仍会采样继续播放的音乐位置。停止任务另有可选的设备包络进度检查点：AudioEnvelope 命令携带具体停止任务 owner 和累计起点 elapsed_us；Web 按暂停感知的 AudioContext.currentTime 采样，原生按已产生采样帧采样。AudioPosition.envelope 回传 owner/elapsed_us，Core 仅接受仍拥有该 Audio 实例的运行中停止任务，进度必须不超过声明时长，不能倒退。先验证整批再修改，旧 owner 或会话记录不影响新声音。

读档与 Cancel 停止任务优先使用设备检查点的当前值，恢复剩余线性段从累计起点继续，避免听到的音量跳回剧情时钟推算值。常值替换清除设备 owner，迟到的旧 ramp 观测不能覆盖已提交值。旧 v2 快照缺检查点时仍使用原逻辑 elapsed。检查点仅接受 AudioStop，恢复验证其类型和进度；不新增作者能力或快照版本号，宿主与 WASM 必须配套。

这份观测不会推进 Story tick、任务逻辑 elapsed、里程碑或执行指令；AudioStop 的 Finished/Cancel、Await 和作用域规则不变。设备先淡至零而逻辑任务尚未结束时，保持静音直到原任务收尾，不把观测伪装成剧情时间推进。这不是音频设备与剧情时钟的全局同步承诺。

Web Audio 使用独立包络 GainNode；玩家音量与事件 gain 使用另一 GainNode。原生音频使用按采样帧推进的包络，两声道同帧使用相同值；暂停 sink 不消耗包络样本。设备输出延迟与 Story 时钟误差需按实际平台单独测量，不宣称样本级跨设备同步。

## 导入与验证入口

LiveNovel 适配将 BGM `STOPSND ... PASS` 转为不阻塞主流的停止任务；非循环语音在源页完成处以 50 ms 淡出停止。循环语音不执行该翻页清理。导入器复用每通道的停止句柄，避免长篇阅读积累无限任务名。

`PLAYSND` 对已有通道的隐式替换，将零时长停止与新声音放在同一个 cue 中，等新媒体准备完成再提交。停止任务先捕获旧声音的具体实例，新声音随后重绑通道句柄；准备延迟、失败或重试不先停旧曲。作者显式 `STOPSND` 的独立停止与淡出时机保持原义；显式再次播放同曲仍从头播放，普通阅读则沿用会话中的原实例。

原生语义回归：`cargo test -p nir-core --test audio_contract`。采样包络及存储回归：`cargo test -p player-desktop --lib`；Linux 执行该命令不代表 Windows 音频设备实测。

构建配套 SDK 后，`npx playwright test --config playwright.nir-next.config.js` 会生成中性工程并检查 WebGL2 的事件增益、连续淡出、暂停、存读档剩余包络及会话清理；`tests/nir-next/audio-gain-tween.spec.js` 审计实例增益补间在设备包络节点上的单条 ramp 与循环存活。该入口不使用私有游戏或外部媒体工具。Windows 真机和硬件 WebGPU 仍需独立验收。

Story 音频自然结束或失败发生在逻辑暂停期间时，Player 按当前 session 与运行中实例校验，并在有界映射中保留每个声音的第一个终态事件。自然结束只接受非循环实例；失败也接受循环实例，保留的错误文字最多 1024 个字符。重复或冲突的后续回调不覆盖首个事件。恢复 Story 后才提交自然结束和后续 VM 指令；暂停期间不反复唤醒宿主。退出/替换会话清空集合，循环实例与陈旧回调不能进入它。Web 使用独立的 BGM、Voice、Sfx 设备时钟及前台 UI 时钟，原生使用每个 Sink 的域暂停与总线暂停合并判断。更改音量或解除一个暂停所有权都不能释放其他所有权。
