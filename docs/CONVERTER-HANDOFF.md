# 转换器与播放器阶段性交接

转换器与播放器的开发备份已整合到主线，尚未发布。最新恢复进度见文末记录；生成工程、媒体、构建产物、存档、部署配置及本机记录不在提交范围内。

恢复时使用了不继承旧开发提交历史的清理快照，避免旧记录中的环境与来源标识随备份传播。主线整合已审阅文件差异，将清理后的改动压成一次提交，保留主线原有历史。

## 当前目标与边界

补齐 LiveMaker / LiveNovel 导入能力，将受支持的语义转换为 NIR 的类型化程序，并验证浏览器播放与恢复体验。部署适配保持在独立仓库，本仓库不包含该适配的配置或安装包。

原始程序仅用于静态格式检查，不执行来源程序。未知语义、缺失剧情资源、未认证的辅助程序和预算超限仍须明确拒绝。媒体构建使用 MP3；WAV 可以作为离线导入中间文件，播放器不提供 WAV 回退。

## 已实现的主要工作

- LSB 116/117 解析及路线适配：分支、子程序返回、预览选项、取消、进度标记、回想入口、部分剧情内菜单调用，以及源位置关联的文本身份。
- 类型化画面能力：有限精灵时间线、源运动曲线、字图、摇动、窗口样式、图层图片与几何继承、自然结束后删除，以及静态头像和姓名图片。
- 播放连续性：媒体准备与页面提交保留会话音频实例；冷恢复保留任务状态、时钟、画面、窗口样式和装饰图片，同时更新交互凭证。
- 大型工程：复用不可变声明和相同剧情片段，保留不同源状态的操作身份；在媒体导出前拒绝重复操作编号或无效生成脚本。
- 有界内容编码：`content.interned-json.v1` 复用 JSON 子树，并直接反序列化为类型化数据。保持 16 MiB 编码输入限制，另设 64 MiB 逻辑展开和 128 层深度限制，校验摘要、引用、键与可达性。
- 长音频导入：Vorbis 分包解码，保留完整采样并限制 PCM 和总导出大小；播放器继续按驻留及绘制预算准入。
- 最新转换修正：认证事件解析忽略末尾换行产生的额外字段，真正的空图片参数仍拒绝；按来源声明识别缺席的 CG 摇动目标；`WAITPLAY` 可解析具名运动任务。

以上能力各有严格的来源形状或指纹限制，不代表支持任意来源脚本。

## 恢复工作的顺序

1. 先构建与代码一致的 CLI、能力 schema 和 Web SDK；避免将新增能力与旧播放器混用。
2. 重新验证具名运动等待和 CG 声明索引的完整路线，继续处理明确报告的兼容性阻塞。
3. 在独立工作目录完成大型工程导出、严格检查、Web 构建、完整路线遍历与真实浏览器测试，再进入独立部署流程。
4. 补齐类型化文字／数字输入：草稿、长度与数值校验、取消不写入、键盘与输入法、冷恢复和陈旧输入拒绝。不能用会暂停剧情音乐的普通菜单替代来源输入语义。
5. 补齐复杂局部变量生命周期、对象状态和有副作用表达式；禁止用常量或空操作代替尚未支持的逻辑。
6. 缺失来源资源保持明确阻塞，不能替换为占位图或静默省略。继续分别记录能力验证、单个转换结果和部署结果。

## 入口与检查

主要实现位于 `crates/nir-compiler/src/import/`、`crates/nir-format/`、`crates/nir-core/`、`crates/nir-content/`、`crates/nir-player/` 与 `crates/nir-presentation/`。行为边界见 `docs/IMPORT.md` 与 `docs/CAPABILITIES.md`。

```sh
cargo fmt --check
cargo test -p nir-compiler --lib
cargo test -p nir-core -p nir-format -p nir-content -p nir-player -p nir-presentation
cargo clippy -p nir-compiler -p nir-core -p nir-format -p nir-content -p nir-player -p nir-presentation --all-targets -- -D warnings
cargo build -p novelc
cargo build -p player-web --target wasm32-unknown-unknown --release
node --test tests/host/*.test.js
python3 scripts/verify_capabilities.py
```

浏览器入口为 `playwright.livenovel-features.config.js` 和 `scripts/serve_livenovel_features.py`。使用 `NIR_TEST_COMPILER`、`NIR_TEST_SDK`、`NIR_TEST_PROJECT`、`CHROMIUM` 指定开发环境；头像专项启用 `NIR_TEST_DECORATION=1`，其余能力开关见对应测试文件。测试项目应放在独立输出目录。

需要外部材料的测试默认忽略，通过环境变量明确传入材料。后续交接继续只记录技术结论，不将个人资料、实际环境地址、绝对路径、来源标题、剧情、来源文件或生成媒体写入代码、文档、提交说明或测试附件。

## 2026-10-10 恢复记录

恢复了构建依赖并重建与代码一致的 CLI、能力 schema、Web SDK 和 Linux 运行时。工具链文件中已有的版本调整保留；Android 构建仍缺 NDK，原生真机验收未完成。本机镜像和 C++ 标准库问题通过独立的本机构建环境处理，没有更改用户全局 Cargo 配置。

本轮修正：显式 `++` 可对字符串／整数的纯字面量按十进制拼接，继续拒绝动态转换和未知浮点格式；LSB117 的顶层条件 Jump 可作为直接入口，并执行条件为假时的正常后续指令，嵌套、禁用和有副作用的条件仍拒绝。中性测试覆盖执行、字符串存档恢复及条件两侧。主线和额外标题入口使用独立路线遍历时，临时剧情函数改用全局唯一编号，避免后一次遍历覆盖前一次的调用别名；回归覆盖两个入口各自的实际执行结果。

大型内容修正：共享内容池通过类型化信封解析，编码表不再误用普通内容数组的十万项上限；普通数组／对象仍保持原有上限，16 MiB 输入、64 MiB 展开、128 层深度及重复字段检查保持有效。资源目录按消费者分组后再拆为每包最多 64 个资源，避免显示少数资源时固定整段剧情的全部资源描述；资源标识、函数身份和媒体保持不变，运行时驻留预算没有扩大。连续提示提交时，当前活动媒体只接管本次准备租约已覆盖的资源；下一提示的目录／媒体由其独立准备阶段准入，避免目录尚在下载时提前读取其成本。回归人为延迟下一目录，检查当前画面与音乐仍已准入，之后能继续提交。

独立 SDK 验证用的字图夹具补齐合法样式声明。独立发布验证脚本新增共享内容池解码、代码包执行作用域及媒体依赖检查，并补恶意输入回归，检查向后引用、键顺序、可达性及输入／展开／深度预算；引擎与发布 CI 已加入该回归入口。

验证结果：编译器单元测试 175 项通过；Core、Format、Content、Player、Presentation 相关测试合计 529 项通过。编译器集成测试 67 项通过。严格 Clippy、格式检查、183 项宿主测试、81 项能力清单检查及独立 SDK 验证通过。真实 Chromium 的 Worker／主线程默认回归 14 项、装饰图片专项 2 项、共享内容专项 2 项通过；最新播放器 SDK 的独立验证及共享内容浏览器专项也已通过。外部路线测试补充仅含计数的进度日志；同一路径重复遇到选择时轮换已启用选项，避免永远选择首项／取消而形成测试假循环。中性 Core 回归覆盖循环后的实际退出，路径和步数上限保持不变。

外部材料验证确认媒体导出、工程生成及当前 SDK 的锁定和严格检查可以完成。导入进程在近似规则未经显式接受时返回非零，即使工程已经写出，也不能将该返回值误判为媒体导出失败；仍须单独通过近似规则验收，才能进入发布或部署。来源、具体规模和实际规则清单仅保留在私有记录中。
