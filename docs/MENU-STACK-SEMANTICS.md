# 有限菜单纵向排列

`ui.menu-stack.v1` 在既有 MenuElement 中增加 `content = {type = "stack", gap = 10}` 容器。它服务于原菜单按条件省略条目后紧凑排列的需求，不执行源循环，也不产生新的控件或资源。

Stack 继承 Group 的变换、透明度、裁切和祖先条件，本身不绘制。它按完整元素声明顺序排列直接子元素：第一个可见子元素的 y 为 0，后续位置增加上一项 `rect.height * scale + gap`。隐藏子元素不占高度或间隔；禁用子元素保留位置和点击屏障。x 保留作者值；子元素必须声明 y 为 0 和正的高度，以避免偏移、占位范围的歧义。

一行可以是 Group 或另一个 Stack，行内仍按自身坐标定位。容器行的 rect.height 是明确的占位高度，不从文字或子节点自动测量；嵌套 Stack 不向父容器回传尺寸。字号放大可能需要作者预留空间或裁切，当前不声明可变高度文本列表。

每个 gap 必须有限且处于 0–1024。每个 Stack 的全部直接子项按声明计算的高度与间隔总和不能超过 8192，包括最后一项后的保守间隔预算，隐藏条目也计入校验预算。仍受 256 个总元素、64 个文字批次、原有层级/缩放及资源预算限制，不提高默认预算。

排列是纯函数，每次从相同局部值、Profile 和阅读服务可用性求得相同位置；不保存游标、不修改 Core 或偏好、不写快照。绘制、裁切、语义区域、指针命中和键盘焦点共用同一坐标结果。控件 ID 继续按完整声明位置分配，兄弟显隐不会重新编号。条件变化依照既有菜单版本规则使旧输入失效。

```json
{
  "id":"rows", "rect":[177,73,400,300],
  "content":{"type":"stack","gap":10}
}
```

子项使用 `parent: "rows"`，可把文字和点击区放在同一个有正高度的 Group 行中。`visible_when` 的局部、Profile 与可选阅读服务条件沿用菜单状态合同。所有目标能力都必须声明，编译器按实际使用保留，源 Program 与分块 runtime root 均校验。

当前验证采用中性菜单；原工程菜单的字体、hover 样式、背景截图、条件对应关系、回调与页面生命周期仍需转换规则及对照验证。纵向排列本身不等于原版系统菜单已迁移。
