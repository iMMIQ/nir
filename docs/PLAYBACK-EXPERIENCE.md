# 播放体验与验收

目标依据：临时播放体验目标文档（2026-10-03）。下面保留完整目标范围；已经完成的机制不代表全部体验已经验收。

## 场景行为

域暂停与总线暂停合并，释放菜单不能释放后台、设备或显式暂停。暂停期间的 Story 音频自然结束或失败只记录当前会话中运行的声音；自然结束只接受非循环实例，失败也接受循环声音。恢复正文后再交给 VM，第一个终态事件保留、重复或冲突回调忽略，替换会话清空。音量调整不修改暂停或作者包络所有权。

Web 为 Story/BGM、Story/Voice、Story/Sfx、ForegroundUi 提供独立设备时钟；前台界面保留单独时钟，不能唤醒后台的剧情声音。原生按每个 Sink 合并域和总线政策。菜单 Voice 暂停与翻页续播分别处理：voice_continue 默认保留作者生命周期，关闭后在真正完成 Dialogue 时停止关联语音；已读快进总是清理关联语音，补全文字或窗口分页不停止。具体绑定、旧作品和终态语义见 READING-SEMANTICS.md。

## Web 输出恢复失败

仅正在调度、未停止且未静音的声音要求设备输出。对应通道收到原生输出 `error` 或不再运行时，冻结正文；已工作的其他通道继续。恢复保留声音实例、阅读位置及其他暂停所有权，不自动跳句或补入等待时间。

输出屏障解除的当轮丢弃此前积累的正文时间，即使检查设备时已经将暂停状态释放，也不能把检查间隔计入剧情。前台界面仍使用独立时间，不因这个正文屏障丢弃自己的运行时间。

同一通道正在等待手势恢复时，连续点击与按键重复不会叠加 `resume()` 请求。政策释放发起的请求允许一次新用户手势接续；暂停后重新释放可重新请求。旧请求的失败不能覆盖新请求，旧请求成功后仍须遵守当前暂停政策。拒绝或同步异常允许重试。

提示区分等待手势、正在恢复、恢复仍未完成与明确失败。需要新手势或请求已被拒绝时，恢复按钮可用；已经由手势授权的请求尚未结束时，禁用恢复按钮并显示正在恢复，超过 1.5 秒则说明仍在等待并提供“打开存档”。设备已关闭时禁用恢复，建议先保存再手动重开；其他明确失败只有能实际再次请求时才提示重试。1.5 秒仅改变说明，不取消请求、不判断设备不可恢复，也不触发自动重试。存档入口在正文且非加载时可用，支持键盘与至少 44px 的触控目标。保存必须由玩家选择槽位，不自动覆盖进度。提示消失以设备状态为依据，不能证明硬件已经发声。

本机 Chromium 默认输出存在 `resume()` 迟迟未完成的复现。失败页面销毁前的 trace 显示输出流创建成功，但音频服务的一次 `OutputController::StartStream` 阻塞约 4.47 秒，随后 Voice/Sfx 才恢复；具体阻塞原因尚未确认。`OutputStream::OnError` 也用于客户端关闭，不能仅按事件名认定平台故障。没有采用未经验证的设备重建、延迟参数或空闲通道方案，也没有静音输出回退。故障注入用例单独使用浏览器静音输出设备，验证冻结、重复输入、提示及 IndexedDB 保存；默认输出回归继续独立保留，静音设备测试不能代替真实输出验收。恢复耗时与当前待处理请求的字段见 DIAGNOSTICS.md；这些 API 计时不能代替实际声音验收。

恢复提示在横竖屏均位于顶部紧凑操作栏下方，宽度随视口调整，长说明在卡片内滚动；菜单入口保持可触控。正文的“继续阅读”只在已准备完成的读档暂停、且没有其他暂停所有权时出现。音频输出受阻时采用声音恢复提示，不能把解除读档暂停的按钮用作设备恢复。

打开菜单或进入后台仍维持当前暂停政策，并保留旧恢复请求的身份。自己的 `suspend()` 可能改变尚未完成的原生恢复目标；解除最后一个暂停原因时重新提交运行目标，不等待被打断的旧 Promise 先完成。未经过自身暂停打断的请求仍合并重复输入；迟到结果不能结算新请求，仍处于菜单或后台时也不能释放暂停。输出恢复期间可通过画布打开菜单，但从受阻状态开始的正文点击始终只用于恢复，不在松手时翻页。

## 完整工作范围

仅重建渲染器时，准备完成后解除本次设备暂停，恢复原有暂停政策，保留当前音频实例和正文位置。它不产生新的读档确认；菜单、后台、外部暂停及已经存在的读档确认仍各自持有暂停。加载真正的存档或回滚时，仍按快照恢复声音实例并等待玩家继续。

共享原生宿主把窗口焦点、遮挡和表面挂起分别记录，任一原因仍成立就保持后台暂停。挂起先暂停现有 Sink、采样声音位置并通知 Player，再释放画布；不再在生命周期回调中等待最多 5 秒存储。存储和解码线程继续收尾，窗口缺失期间不执行 owner 更新，回执在重新绑定画布后正常交付；不能据此保证系统杀进程前所有未完成写入都已落盘。无窗口期间仍记录焦点和遮挡事件，恢复不会遗漏较早到达的焦点恢复，也不会释放其他暂停原因。计时基准在生命周期切换时重置，不将后台或画布重建时间补入剧情。声音启动和域／总线恢复还受宿主可见性约束，迟到的恢复命令不能在后台重新出声。

本地 winit 0.30.13 的 Android 路径将原生窗口创建／销毁映射到 Resumed／Suspended；活动的 Pause／Resume 另更新内部 running 状态。本次修复覆盖表面生命周期与窗口可见性的组合；Android 音频焦点、系统设备变化和真实锁屏仍需真机验证。阶段 27 的状态控制器结合共享 Player 的 7 项回归验证了未收到焦点事件的挂起、迟到焦点、菜单／读档暂停所有权、原音乐任务保留和时钟恢复，不是实际 Android 窗口或扬声器测试。证据见 `reports/experience-native-lifecycle-validation.json`。

原生音频设备的打开和销毁在独立 worker 完成，平台 stream 留在该线程，owner 只接收 mixer。设备错误先暂停声音与正文，再自动尝试一次恢复；失败后可按 F8 重试，窗口重新可见时也可重试。请求和回复有界，generation 排除旧设备回调及迟到的打开结果；每个候选配置有自己的错误回调。菜单、后台、读档确认和关闭暂停各自保留所有权，设备等待不补入剧情时钟，按住快进被清除。

阶段 33 在共享原生画布的正文／结束页增加声音恢复提示，保留原场景，提供至少 44 px 的重试及菜单按钮；打开设备期间禁用重试。菜单、历史和存档页不被提示遮挡，玩家可进入菜单自行保存。恢复手势由宿主处理，不作为剧情输入；按下到松手之间即使设备恢复、提示消失，也消费这次鼠标或触摸配对，第二根手指不能替代原手势。受阻时的继续、翻页、自动和快进输入在本轮设备回执之前判断并丢弃，避免 Ready 与输入同轮到达时跳句。设备恢复仍保留读档等待继续的暂停；Space／Enter 可重试，Esc／返回可打开菜单。完整键盘与作者菜单矩阵、Android 系统音频焦点、实际设备更换及真机触控仍需验收。

更换 mixer 时重新连接同一个 Sink 队列，保留原音乐任务、样本游标、前奏一次的循环区间、重采样器和淡化状态。整段循环的微秒 seek 改为选择完整的最近音频帧，与循环区间的时间约定一致；旧逐样本纳秒舍入会使 44.1 kHz 立体声从右声道开始，并使长曲位置累积偏差。有限语音的既有 floor-frame seek 保持。软件 mixer 回归覆盖游标、前奏、采样率变化和已有淡化，不能代替实际设备／循环接点听感；同机 1/4/8 路软件 mixer 对照的中位耗时增加约 3.9%/8.7%/10.3%，逐组样本校验和相同；入口优化但 Rodio 依赖为 debug 构建、无设备或锁竞争，尚不证明真机回调预算。测量见 `reports/experience-native-output-queue-bench.json`。

阶段 32 的 58 项原生逻辑测试在显式 tmpfs 测试目录通过，Clippy、fmt、Web/Linux SDK 和中性包校验通过；当前物理文件系统上的两轮全包仍有存储回执超时，系统调用记录包含最长 15.86 秒的成功 fsync。tmpfs 结果只隔离逻辑与磁盘等待，不证明持久存储延迟达标。证据为 `reports/experience-native-output-validation.json`。当前 Linux 宿主在独立 PipeWire 虚拟声卡完成阅读、存读档和退出，录制样本存在，但初次录音严重削波。绕过 NIR，直接用 pw-play 播放峰值 0.0712 的低幅参考素材，仍在相同虚拟链路录得削波；f32 raw 和 s16 WAV 结果一致。该链路尚不能用于声音质量验收，原因仍待定位，不据此调整作品增益。范围见 `reports/experience-native-output-gui-virtual.json` 与 `reports/experience-native-output-capture-isolation.json`；均不证明物理扬声器或 Android。

原生正常窗口关闭新增独立暂停原因：暂停声音与正文、清理按住和触摸输入，窗口标题显示关闭中并提示 Esc 取消。事件循环继续交付存储及文件对话框结果，待所有存储请求完成、已接受的 owner 事件和对话框处理完后才退出；不阻塞等待，不为关闭重新创建 GPU 或交付媒体上传。SaveFailed／SaveFault／PersistenceFailed／ExportFailed 取消本次关闭，保留 Player 的失败状态，玩家可以再次保存；Esc 只取消关闭，已提交的写入继续完成。释放关闭暂停保留菜单、焦点、遮挡和挂起等其他原因，不补入存储等待时间。存储线程意外结束而仍有请求时报告 Fatal，不把丢失回执当作保存成功。这个路径不保证系统杀进程、宿主致命错误或诊断 smoke 退出时的未完成写入。
