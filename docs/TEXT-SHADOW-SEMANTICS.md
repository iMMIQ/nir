# 单层正文阴影

主题 dialogue 可选 shadow；旧主题缺省无阴影，非空声明要求 `text.shadow.v1`，编译器按实际配置推导。源 Program 和 runtime root 都校验声明。

```toml
[dialogue]
shadow = { offset = [2.0, 2.0], color = [0.0, 0.0, 0.0, 0.7] }
```

offset 每轴为有限 -16..16，单位与对白布局坐标一致，随自定义舞台缩放；RGBA 各分量为有限 0..1。只支持一个无模糊阴影，不提供多层、描边或发光。当前作用域为对白正文，不自动给系统按钮、说话人和历史页添加阴影。

阴影是绘制属性，不是第二份 Dialogue：复用正文的字体计划、文字分段、字素揭示、滚动和换行宽度，只移动画笔位置。先绘阴影，再绘正文；阴影统一颜色，不继承强调色。可见范围受原正文区域及外部裁切共同约束，不改变阅读分页、命中或辅助语义。阴影 alpha 乘正文有效 alpha，故消息根整体/文字淡出与玩家临时隐藏同样作用于阴影。

共享渲染路径在存在阴影时增加最多一份单色塑形缓存和绘制项，沿用原有缓存回收；不引入字体或图片资源，不增加 Core 状态、快照字段或故事指令。无阴影的旧路径不复制文字集合。恢复仍以同一发行主题为准。

实际平台验证按进度文档记录；共享 GPU 代码不等于 Windows 实机或硬件 WebGPU 认证。导入器当前不推断来源阴影颜色、偏移和字体设置，需固定来源证据后明确映射，不能把上述主题能力声明为原作样式已经精确迁移。
